## 1. 用户反馈与处理

| 反馈 | 根因 | 处理 |
| --- | --- | --- |
| 笔记已修改，「提交改动」却显示「没有需要提交的改动」 | 自动同步在保存后 5 秒先 `syncCommit` 再 `syncPush`；commit 已成功、push 认证失败被 `catch {}` 静默吞掉，用户手动提交时工作区已干净 | `commit()` 返回 `reason=unpushed` 并提示「还有 N 个提交未推送」；`autoSync` 失败可见化；状态卡片显示 `lastError` |
| 「自动同步也进行」但远端没更新 | 同上，push 失败被吞 | 后台失败写 `app.sync.state`、派发 `dbx:sync-error`、认证错误每 2 分钟最多提示一次 |
| 手动推送 Gitee 认证失败 | ① `GIT_ASKPASS=echo` 把提示语当成用户名发给 Gitee；② `provider` 默认 github，对 gitee.com 拼 `x-access-token`；③ 非快进重试写死 `origin` 丢凭据；④ 令牌未编码 / 掩码污染 / Gitee 用户名敏感 | 移除 ASKPASS、按主机判定平台、Gitee 多候选用户名、URL 编码、掩码识别、全链路统一认证目标、友好报错 |
| （附带）工作区不是独立仓库 / 笔记被忽略 | `commit()` 无仓库根校验；`.gitignore` 排除的 .md 不会被 `add -A` 纳入 | 新增 `require_repo()`；状态与提交结果回报 `ignored[]` |

## 2. 新增 / 优化 / 修复清单

### 新增

- `sync/check` RPC：用与推送相同的凭据执行 `git ls-remote --heads`，返回 `ok` / `message` / `effectiveProvider` / `username` / `maskedToken`。
- 「测试连接」按钮（设置 → 同步 → Git 通道）。
- 「Gitee 账号名（可选）」输入框，仅当生效平台为 Gitee 时显示。
- 状态卡片：生效平台、被忽略的笔记文件、上次同步失败（含后台自动同步）。
- 同步运行状态 `app.sync.state`：`lastError` / `lastErrorAt` / `lastErrorStage` / `lastSuccessAt` / `lastSuccessStage`。

### 优化

- 提交空改动按 `clean` / `unpushed` / `ignored` 分级提示，不再一律弹绿色成功。
- `auth_plan()` 集中构造认证候选，`push` / `pull` / `fetch_snapshot` / `check` 复用同一套策略。
- Gitee 认证失败时按「自定义账号名 → oauth2 → 仓库 owner」依次重试，仅认证类错误才重试。
- 错误信息经 `sanitize()` 打码，明文与 URL 编码后的令牌都不会出现在 UI / 日志。
- `githistory.rs` 按远端地址判定平台，历史版本入口不再依赖平台选项是否切换。

### 修复

- `apply_git_env()` 移除 `GIT_ASKPASS=echo` / `SSH_ASKPASS=echo`。
- `push()` 非快进重试沿用 `used_target`，不再退回裸 `origin`。
- `authorized_url()` 按远端主机判定平台，自建域名回退用户配置。
- 令牌 / 用户名百分号编码；已有 `userinfo` 的 origin 去重。
- `commit()` / `pull()` / `push()` / `check()` 前置仓库根校验。

## 4. 数据库改动

**无**。本版不新增表、不改字段、不新增索引。

新写入的 `settings` 行由现有表承载，SQL 为可重复执行的 upsert：

```sql
-- 仅为说明，部署时无需手工执行；后端在同步成功 / 失败时自动写入
INSERT INTO settings (key, value, updated_at) VALUES ('app.sync.state', '{...}', <now_ms>)
ON CONFLICT(key) DO UPDATE SET value = excluded.value, updated_at = excluded.updated_at;
```

`app.sync` 配置新增可选字段 `gitUsername`，缺省为 `""`，由 `default_options()` 补齐。

## 5. 部署流程

1. **停止**：退出旧版插件（宿主会结束 Sidecar 进程）；如手工部署，先结束占用本地 RPC 端口的旧 `backend.exe`。
2. **备份**（可选）：复制 `%DBX_PLUGIN_DATA_DIR%/dbx-note.db` 与工作区目录。
3. **脚本顺序**：无需执行 SQL / 迁移脚本。
4. **替换**：用 0.5.8 的 `.dbxp`（含新版 `backend` 与 `ui/`）覆盖安装。
5. **启动**：宿主拉起 Sidecar；启动日志应显示握手版本 `0.5.8`。
6. **端口校验**：确认 Sidecar JSON-RPC 可响应 `sync/status`（新增字段均为可选，旧前端不会报错）。
7. **验证**：
   - 设置 → 同步 → 状态卡片显示「生效平台」；
   - 点「测试连接」，应返回「连接成功」或明确的认证失败原因；
   - 填 Gitee 私人令牌（勾选 `projects` 权限）与可选账号名，再点「测试连接」；
   - 修改一篇笔记，等自动同步后查看远端是否已更新；
   - 手动点「提交改动」，若已自动提交应提示「还有 N 个提交没推送」而不是「没有改动」。
8. **回滚**：退回 0.5.7 安装包即可。`app.sync.state` 为附加键，旧版不读取、不受影响；`gitUsername` 对旧版是未知字段，会被忽略。

## 9. 追加变更：大纲性能与全级别快速定位

### 9.1 新增 / 优化 / 修复

| 类型 | 内容 |
| --- | --- |
| 优化 | 大纲不再订阅 `content` 做全量 Markdown 解析；改由编辑器按 ProseMirror `transaction` 增量维护标题索引（只重扫变更区间），标题内容未变时不触发面板重渲染 |
| 修复 | 二~六级标题点击不定位：跳转载荷由「标题文本」改为「标题 id」，用索引里的 `pos` 设选区 + `nodeDOM(pos)` 在明确的滚动容器里居中滚动；带粗体 / 公式 / 链接 / 重复文本的标题同样可定位 |
| 新增 | 源码模式大纲兜底：用 Markdown 文本解析标题，点击按行号跳到 CodeMirror 对应行 |
| 新增 | `outline.untitled` 空标题兜底文案（简中 / 英，其余语言回退英文） |

### 9.2 接口 / 配置 / 依赖 / 数据库

- **无新增后端 RPC、无新增外部依赖、无表结构变更、无 SQL / 迁移脚本**；仅复用已有的 `@tiptap/pm/transform`（`Mapping` / `Step`）。
- 前端新增模块 `src/lib/outlineIndex.ts`、`src/lib/outlineStore.ts`；`editorBus.scrollToHeading` 的入参语义发生变化，仅供本项目内部调用，无外部契约。
- 新增 DOM 约定 `data-editor-viewport-root="true"`（编辑器滚动容器）、`data-outline-id` / `data-outline-level` / `data-outline-source`（大纲面板）；事件 `dbx-note:scroll-to-heading` 的 detail 由标题文本改为标题 id，新增 `dbx-note:scroll-to-line`。

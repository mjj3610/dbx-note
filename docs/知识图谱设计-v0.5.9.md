# wiki 知识图谱设计（v0.5.9 / dev 分支）

> 状态：设计已确认，代码已在 `dev` 分支实现；本文件是决策记录，不是待办清单。

## 1. 需求与方向修正

最初的设计是「扫描 Markdown 链接 → 在左侧栏加第 5 个 tab 画小图」。用户否掉了这个方向，明确要求：

1. 图谱应**根据知识库向量化结果**生成，并支持「发现 / 刷新」；
2. 点击「图谱」要在**中间大区**显示，并与**知识块联动**；
3. 重新评估性能与兼容性。

## 2. 核心结论

图谱是向量库的**只读派生视图**，不是新一轮索引：

- 现有 `load_chunks()` 已经把 `filename / chunk_id / content / embedding / path / title` 一次读全；
- `cosine()` / `lexical_terms()` / `bm25_score()` 都是现成纯函数；
- `kb_meta` 里有 `embeddingDimension` 与 `lastIndexedAt` 两个天然水印；
- 因此**不重新调用 embedding API、不写表、不扫 Markdown 链接、不新增权限**。

参考项目 NoteGen v0.39.2 没有 wiki 图谱，这部分属于自定义扩展，语义上复用其 `stores/vector.ts` 的知识块概念。

## 3. 图模型

| 图元素 | 来源 | 说明 |
| --- | --- | --- |
| 来源节点 | `knowledge_sources` + `vector_documents.filename` 聚合 | 默认粒度，向量按分块均值池化 |
| 知识块节点 | `vector_documents` 每行 | 展开粒度，`chunk_id` 排序 |
| 相似边 | `cosine(chunk_i, chunk_j) ≥ 阈值`，每节点取 top-k | 语义关联，跨文档才有意义 |
| 邻接边 | 同 `filename` 且 `chunk_id` 相邻 | 结构连接，零相似度计算 |
| 词法边 | 对称 BM25，归一化到 0~1 | `configured=false` / 占位向量 `[0.0]` 时降级 |
| 水印 | `count` + `max(updated_at)` + `sum(included)` + `dimension` + `lastIndexedAt` | 覆盖 reindex / flags / deleteVectors / snapshotImport |

**边表示「相似」而不是「引用」**：没有显式 `[[wikilink]]`，UI 必须标注边类型，避免误解成 wiki 链接图。

## 4. 生成 / 发现 / 刷新

| 动作 | 触发 | 数据来源 | 成本 |
| --- | --- | --- | --- |
| 生成 | 首次进入图谱页签 / 改参数 | `kb/graph` 一次读全库算相似边 | 一次 SQLite 读 + 有界计算，按水印缓存 |
| 发现 | 点节点「发现关联」/ 双击 | `kb/graph/neighbors` 以该节点取 top-N 组成局部子图 | 单次 `O(N·dim)`，不调 embedding |
| 刷新 | 手动按钮 / `dbx:kb-reindexed` / 窗口回前台 | 比对 `lastIndexedAt` 与 `computedAt` 标脏后重拉 | 后端水印变化才重算，否则缓存命中 |

`dbx:kb-reindexed` 由 `rpc.ts` 的所有知识库写入类 RPC 统一派发，避免文件树 / 设置页 / 自动索引多处漏补。

## 5. 中间大区与联动

`App.tsx` 中间 Panel 改成：编辑器 / 画布**始终挂载**，用 `hidden` 切换显隐，图谱作为覆盖层放在同一 Panel。

> 这是唯一必须规避的兼容性坑：若写成 `graphMode ? <GraphWorkspace /> : <EditorPane />`，
> 切回时会卸载并重建 Tiptap / CodeMirror，丢掉 undo 栈、未保存内容、大纲标题索引与滚动位置。
> 同时不改 `canvasPath`，画布状态也不受影响。

四条联动路径：

1. 图谱 → 知识块：点节点，右侧 `ChunkDetail` 显示 `excerpt`（后端节点带 600 字摘要）。
2. 知识块 → 原笔记：`setTab('files')` → `notes.open(path)` → 派发 `dbx-note:reveal-chunk`；`EditorPane` 有限次重试，`MarkdownEditor` 把摘要与文本节点压成紧凑串做包含匹配后设选区并居中滚动。
3. 图谱 → 发现：局部子图按 id 合并进当前快照。
4. 知识库 → 图谱：写入 RPC 派发事件标脏，`checkStale()` 再核一次水印。

## 6. 性能评估

`dim` 常见 768 / 1024 / 1536，`MAX_SEARCH_CHUNKS = 20_000`，实际个人笔记库多为 200~2,000 chunks。按 `dim = 1024` 粗估：

| chunks N | 朴素 N² 对数 | 乘法量 | Rust 全量粗估 | 本实现 |
| --- | --- | --- | --- | --- |
| 200 | 19,900 | ~20 M | < 50 ms | < 10 ms |
| 1,000 | 499,500 | ~512 M | 0.3 ~ 0.8 s | 来源粒度聚合后 ≤ 20k 对 |
| 2,000 | 1,999,000 | ~2.0 G | 1.5 ~ 3 s | 300 节点上限 → 45k 对 |
| 20,000 | 200 M | ~205 G | 不可接受 | 词法倒排取 48 候选 + `truncated` |

四条硬约束：

1. **embedding 绝不离开 Sidecar**（20,000 × 1024 × 8B ≈ 164 MB）；只传节点 / 边，约 100~200 KB。
2. 默认「来源粒度」先把分块聚合成几十个节点再算两两余弦；`GRAPH_EXACT_LIMIT = 900` 以上才启用词法候选剪枝，保证语义上不漏掉「无字面重叠但向量相近」的关联。
3. 后端按水印缓存最近一次快照；前端单 flight + 序号丢弃旧响应，仅页签激活 / 手动操作才发 RPC，不与保存 / 同步抢通道。
4. 前端只渲染不算相似度：纯内联 SVG + **固定 70 轮**的力导向布局（无 rAF 常驻动画、无 Worker、无 CDN），缩放平移只改 `<g transform>`。

## 7. 兼容性评估

| 维度 | 现状 | 结论 |
| --- | --- | --- |
| `manifest.permissions` | `[]` | 插件自身 Sidecar 内部 RPC，无需改权限 |
| 表结构 | 3 张表已存在 | 只读派生，缓存放内存，零迁移 |
| 多厂商多模型 | `embeddingDimension` 已有 guard | 维度进水印，换模型旧快照自动失效 |
| 未配置 embedding | `status='lexical'`，占位向量 `[0.0]` | 降级 BM25 词法边，UI 标注策略 |
| 快照导入导出 | 会改 `lastIndexedAt` | 天然触发失效 |
| 前端依赖 | 只有 `mermaid`，无 d3 / cytoscape | 零新增依赖 |
| CSP / Worker | 普通 module，无 Worker | 计算全在后端，不引 Worker / CDN |
| 主题 | 深浅色跟随设置 | 节点用 `currentColor` + Tailwind 语义色 |
| 编辑器 / 画布 | 挂在中间 Panel | `hidden` 保活（关键风险点） |
| 窄屏 | `MobilePane = sidebar/editor/chat` | 图谱作为 editor pane 的一种视图 |
| i18n | 5 语言 | zh-CN / en 全量，ja / ko / th 核心词 + 英文回退 |

## 8. 风险与边界

- **阈值敏感**：不同 embedding 模型 cosine 分布差异极大。实现以「每节点相对 top-k」为主，绝对阈值只作滑杆微调；词法分支把原始 BM25 归一化到 0~1 后阈值才有稳定语义。
- **孤立节点**：`degree = 0` 折叠为「未关联」，不占画布中心。
- **大库**：`maxNodes = 300` / `maxEdges = 600` 硬上限，超出返回 `truncated` 并提示聚焦某个节点继续发现。
- **chunk → 原文定位**：`chunk_overlap = 200` 会让同一段文本落在多个块里，采用 16 / 10 / 6 字递减短针兜底。
- **语义图 ≠ 链接图**：这是产品语义边界，不是 bug；后续若要真正的 wiki 引用图，应另建 `[[wikilink]]` 解析层，不与相似边混在一起。

## 1. 变更概览

### 1.1 新增

**插件骨架**

- `manifest.json` v1：workbench 贡献点、`entrypoints.ui`（`ui/index.html`）、`entrypoints.backend`（`bin/windows-x64/backend.exe`）、中英本地化。
- `dbx-plugin.toml`：`schema_version = 1`，`[backend] language = "rust"`，随包分发 `assets / ui / LICENSE / THIRD-PARTY-NOTICES.md / licenses`。

**前端（Vue → React + Vite 单文件）**

- 三栏可拖拽工作台（左：文件 / 记录 / 大纲；中：编辑器；右：AI 助手）+ 顶部工具栏 + 底部状态栏。
- 文件树：展开收起、新建笔记 / 文件夹、重命名、删除二次确认、右键菜单。
- 编辑器：Tiptap 可视化 + CodeMirror 源码双模式、格式浮条、表格 / 任务列表 / 代码高亮、800ms 防抖自动保存。
- 记录：文本 / 链接 / 待办、标签与时间过滤、勾选后 AI 整理成新笔记。
- AI 助手：多会话、流式输出、引用当前笔记、结果插入笔记。
- 全局搜索、设置弹窗、目录选择器、删除确认框。
- i18n：简中 / 英 / 日 / 韩 / 泰（后三者未覆盖词条回退英文）。

**后端（Rust Sidecar）**

- stdio JSON-RPC（DBX Plugin Protocol v1），握手、方法分发、逐请求线程模型。
- 工作区文件：树、读写（原子写）、新建、重命名、删除、全文搜索、目录浏览、图片落盘。
- SQLite：记录 / 标签 / 会话 / 消息 / 设置 / 文件历史。
- AI 代理：OpenAI 兼容非流式与 SSE 流式（后台线程累积 + 前端轮询），模型列表，通用 HTTP。

**工程与测试**

- `scripts/devhost.mjs`：无 DBX 客户端时的开发宿主（静态服务 + 真实 Sidecar + 注入 `window.dbxPlugin`）。
- `scripts/sidecar-check.mjs`：22 项后端协议断言。
- `scripts/smoke.mjs` / `scripts/e2e.mjs`：界面冒烟 10 项、端到端 19 项。
- `scripts/mock-ai.mjs`：OpenAI 兼容假模型服务。
- `scripts/package.mjs`：使用已构建 Sidecar 直接产出 `.dbxp`。

## 2. 接口变更

新增 Sidecar 方法（全部为新增，无破坏性变更）：

| 分类 | 方法 |
| --- | --- |
| 握手 | `plugin/initialize`、`ping` |
| 工作区 | `workspace/describe`、`workspace/set`、`workspace/reset` |
| 目录 | `fs/listDirs`、`fs/mkdir` |
| 文件 | `fs/tree`、`fs/read`、`fs/write`、`fs/create`、`fs/rename`、`fs/delete`、`fs/stat`、`fs/search`、`image/save` |
| 记录 | `record/list`、`record/create`、`record/update`、`record/delete`、`tag/list`、`tag/create`、`tag/delete` |
| 会话 | `chat/list`、`chat/create`、`chat/rename`、`chat/delete`、`chat/messages`、`chat/append` |
| 设置 | `settings/get`、`settings/set`、`history/list` |
| AI | `ai/chat`、`ai/start`、`ai/poll`、`ai/cancel`、`ai/models`、`net/request` |

约定：

- 请求/响应均为 JSON-RPC 2.0 单行 JSON；错误码 `-32601`（方法不存在）、`-32602`（参数非法）、`-32000`（业务/系统异常）。
- 路径参数一律使用工作区相对路径、`/` 分隔；`..` 与绝对路径注入会被拒绝。
- 分块/大文件：单次写入建议 ≤ 1MB 文本；AI 流式用 `ai/start` + `ai/poll` 轮询，单次最长 180 秒。

## 4. 数据库变更

首次创建，全部为 `CREATE TABLE IF NOT EXISTS`，**可重复执行**。
初始化由 Sidecar 启动时自动完成，无需手工执行；下表用于审计与灾备重建。

```sql
-- 键值配置：value 存 JSON 字符串
CREATE TABLE IF NOT EXISTS settings (
    key        TEXT NOT NULL PRIMARY KEY,
    value      TEXT NOT NULL,
    updated_at INTEGER NOT NULL
);

-- 碎片记录：type ∈ text/link/todo/image/file；archived ∈ 0/1
CREATE TABLE IF NOT EXISTS records (
    id         TEXT NOT NULL PRIMARY KEY,
    type       TEXT NOT NULL DEFAULT 'text',
    content    TEXT NOT NULL,
    meta       TEXT NOT NULL DEFAULT '{}',
    archived   INTEGER NOT NULL DEFAULT 0,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_records_created ON records (created_at DESC);

-- 标签：name 唯一
CREATE TABLE IF NOT EXISTS tags (
    id         TEXT NOT NULL PRIMARY KEY,
    name       TEXT NOT NULL UNIQUE,
    color      TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL
);

-- 记录-标签多对多
CREATE TABLE IF NOT EXISTS record_tags (
    record_id  TEXT NOT NULL,
    tag_id     TEXT NOT NULL,
    PRIMARY KEY (record_id, tag_id)
);
CREATE INDEX IF NOT EXISTS idx_record_tags_tag ON record_tags (tag_id);

-- 会话与消息：messages.role ∈ user/assistant/system
CREATE TABLE IF NOT EXISTS chats (
    id         TEXT NOT NULL PRIMARY KEY,
    title      TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS messages (
    id         TEXT NOT NULL PRIMARY KEY,
    chat_id    TEXT NOT NULL,
    role       TEXT NOT NULL,
    content    TEXT NOT NULL,
    meta       TEXT NOT NULL DEFAULT '{}',
    created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_messages_chat ON messages (chat_id, created_at);

-- 笔记快照（预留回滚）
CREATE TABLE IF NOT EXISTS file_history (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    path       TEXT NOT NULL,
    content    TEXT NOT NULL,
    created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_history_path ON file_history (path, created_at DESC);
```

数据脚本：无初始数据。首次启动自动建立默认工作区目录，无需插入记录。

## 5. 部署流程

### 5.1 构建

```bash
npm ci
npm run typecheck
npm run backend        # 产出 backend/target/release/backend.exe
npm run build          # 产出 ui/
npm run pack:local     # 产出 release/com.mjj3610.note-0.1.0-windows-x64.dbxp
```

### 5.2 安装 / 升级

1. **停止**：在 DBX 中关闭该插件的所有工作台窗口（若有旧版本，先在插件管理里禁用）。
2. **备份**（升级时）：复制 `DBX_PLUGIN_DATA_DIR`（生产为
   `D:\Program Files\DBX\data\plugin-data\com.mjj3610.note`，开发为 `%APPDATA%\dbx-note`）。
3. **安装**：DBX → 插件管理 → 从本地安装 → 选择 `.dbxp`。
4. **启动**：打开「笔记」工作台。
5. **端口校验**：本插件不监听端口；如使用 `npm run devhost`，校验 `http://127.0.0.1:5195/` 返回 200。
6. **验证**：
   - 工作台正常渲染，状态栏显示工作区路径与文件数；
   - 新建笔记 → 输入文字 → `data 目录/workspace` 下出现对应 `.md`；
   - 设置 → AI 模型填地址与 Key → 测试连接成功 → 对话有流式回包；
   - 记录 → 新增一条 → 勾选 → 整理成笔记生成新文件。
7. **回滚**：见 5.3。

### 5.3 回滚

- 升级失败：禁用新版本 → 安装上一版本 `.dbxp` → 恢复第 2 步备份的数据目录。
- 本次为首次发布，无上一版本；卸载时的工作区 Markdown 文件不会被删除（仅删除插件数据目录内的 `workspace/`）。

### 5.4 环境差异

| 环境 | 数据目录 | 说明 |
| --- | --- | --- |
| 开发 | `%APPDATA%\dbx-note`（未下发 `DBX_PLUGIN_DATA_DIR` 时回退） | `npm run devhost` 可指定 `--data` |
| 测试 | 由宿主下发 `DBX_PLUGIN_DATA_DIR` | 与生产隔离，可整目录替换做回归 |
| 生产 | `D:\Program Files\DBX\data\plugin-data\com.mjj3610.note` | 升级前必须备份 |

## 7. 已知问题与规避

1. **图片不渲染**：宿主 CSP `default-src 'none'` 覆盖 `img-src`，本地 / 远程图片均无法显示；文件树暂不列图片。
2. **官方 CLI 打包需要 MSVC**：`dbx-plugin dev/package` 固定 msvc target；无 MSVC 时用 `npm run devhost` + `npm run pack:local`。
3. **单编辑区**：多标签页、分屏待实现。
4. **画布 / 知识库 / 同步 / MCP** 未实现，见 README 路线。

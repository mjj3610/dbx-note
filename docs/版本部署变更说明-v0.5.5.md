## 1. 变更背景

用户提供三张截图，指出两类问题：

1. 参考项目文件树的「笔记操作功能」本项目还有缺失 —— 顶部「更多」菜单与节点右键菜单；
2. 0.5.4 上线后底栏导出有实际缺陷：
   - Markdown / HTML / JSON / PDF 四种类型点击后**都导出成 `html` 格式**；
   - 导出时弹出的系统「另存为」窗口**显示在软件下面**，没有置顶到最上层。

只读对照参考项目 `file-more-menu.tsx` / `file-item.tsx` / `file-actions.tsx` 后，把菜单逐项拆成
「文件视图 / 远程文件 / 知识库 / 导入」四组与「节点右键」两组，逐条映射到本项目已有能力或新增 RPC。

导出两个 bug 先用 `.tmp/export-probe.mjs` 拦截 `/rpc` 复现：自动落盘模式下 `markdown` / `html` /
`json` 三种 `dialog/saveFile` 的参数、扩展名、正文、落盘文件**都正确**，因此问题不在前端分支，
而在**原生对话框状态复用**与 **PDF 在 iframe 沙箱里静默降级**两条路径。

## 3. 修复：四种导出都变成 HTML

### 根因

| 路径 | 问题 |
| --- | --- |
| `GetSaveFileNameW` | 未显式指定 `nFilterIndex`，某些 Windows 版本沿用上一次的过滤器索引；用户在文件名里留下旧后缀（如 `笔记.html`）时，旧实现只在「没有后缀」才追加，得到 `笔记.html.md` 或干脆沿用 `.html` |
| PDF | DBX 插件页跑在 iframe 里，`print()` 常被沙箱静默吞掉；点了没反应后降级导出普通 `笔记.html`，用户看到的文件还是 HTML |

前端 `data-export-format` 传参、`exportMarkdown()` 分支、`dialog/saveFile` 的正文与扩展名
在探针里均正确，所以修复集中在 Sidecar 路径规范化和 PDF 降级可辨识性。

### 修复

1. `ofn.nFilterIndex = 1`，每次打开都从目标格式的过滤器开始。
2. 新增 `normalize_export_path(path, extension)`：**一律**按目标格式规范后缀，
   先 `with_extension("")` 剥掉旧后缀再拼目标后缀；`sanitize_export_name()` 同样先
   `file_stem()` 再重建，杜绝双后缀。
3. `printPdf()` 优先用 `window.open('', '_blank')` 顶层独立窗口打印（不受 iframe 沙箱约束），
   失败才退回隐藏 iframe；两条路都不通时导出 `笔记.print.html`，提示语明确写
   「用浏览器打开后打印为 PDF」。
4. 补两个 Rust 单元测试：
   `export_path_always_ends_with_target_extension`、
   `export_name_never_keeps_a_foreign_extension`。
5. e2e 补四格式落盘断言（Markdown 正文、HTML 文档骨架、JSON 为 Tiptap 文档）。

## 4. 修复：「另存为」窗口不置顶

### 根因

Sidecar 是**无窗口的后台进程**，没有前台窗口权限；0.5.4 里 `ofn.hwndOwner = NULL`，
系统把对话框当成无主窗口，容易落在 DBX 主窗口下面，看起来像「没弹出」。

### 修复

```text
focus_host()                       // 先激活宿主窗口
  → GetForegroundWindow()          // 作为 ofn.hwndOwner
  → OFN_ENABLEHOOK + lpfnHook
      WM_INITDIALOG:
        SetWindowPos(HWND_TOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_SHOWWINDOW)
        BringWindowToTop()
        SetForegroundWindow()
```

`SetWindowPos(HWND_TOPMOST)` 不需要前台权限，能可靠把模态框提到最上层；
`BringWindowToTop` / `SetForegroundWindow` 再补一次焦点。自动化环境仍用
`DBX_NOTE_EXPORT_AUTO_DIR` 跳过模态框写固定目录，回归不受影响。

## 6. 文件树右键菜单与快捷键

新建文件 / 新建文件夹、展开 / 折叠 / 全部折叠、查看目录、从模板新建笔记、
知识库（更新本篇索引 / 全部重新计算）、剪切 `Ctrl+X`、复制 `Ctrl+C`、创建副本、

- 快捷键用「最近一次 `pointerdown` 落在 `[data-file-tree]` 或 `[data-tree-menu]` 上」的

## 7. 知识库的等价映射

参考项目「知识库」是向量数据库；本项目是本地优先 + 全文检索，没有 embedding 服务。
因此把菜单里的知识库动作等价映射到工作区 `.dbx-note/kb-index.json` 的**笔记索引快照**
（路径 / 标题 / 摘要 / 字数 / mtime）：

- 索引是工作区内的普通 JSON 文件，随云同步一起被带走；
- 「全部重新计算」= `kb/reindex` 全量重建，「自动更新」= 每次保存后 `kb/upsert` 单篇；
- 「上传 / 下载知识库」= 通过系统另存为导出快照 / 从快照恢复；
- 导出的是**索引**，不是笔记正文；恢复正文仍走云同步。

## 9. 安全边界

- `safe_import_path()` 逐段过滤 `/ \ : * ? " < > |`、控制字符、`.` / `..`；
  再经 `files::safe_join()` 做 `path_within(root, target)` 校验，防路径穿越。
- 单次导入最多 500 个文件、单文件 8 MiB；只写入 `md/markdown/txt/mdx` 与
  `png/jpg/jpeg/gif/webp/svg` 白名单。
- `fs/copy` / `fs/move` 拒绝 `target == source`，并拒绝把目录移动进自身；
  同名冲突自动加「 副本」后缀。
- `kb/upsert` 拒绝空路径、目录、非文本文件；`kb/import` 拒绝缺少 `docs` 的快照。
- 知识库索引写到工作区隐藏目录 `.dbx-note/`，扫描时显式跳过 `.git` / `node_modules` 等目录。

## 1. 变更概览

### 1.1 新增

**斜杠命令面板（对齐 NoteGen 输入 `/` 的 ListSelect）**

- 在**空段落行首**输入 `/` 弹出面板：左栏分类（AI 4 / 标题 6 / 列表 3 / 块级 6 / 公式 2 / 图表 8，共 25 条），
  每类带数量，`‹ ›` 箭头按 3 组一页翻页并显示 `1/2` 页码；右栏命令列表带图标 + 标题 + 说明，右上 `↑ ↓` 逐条滚动。
- 键盘：`↑↓` 选项、`←→` 切分类（有搜索词时不拦截横向移动）、`Enter` 执行、`Esc` 取消（连行首 `/query` 一起清掉）。
- 继续输入即为搜索：匹配中文名、英文名与关键词（如 `bullet` / `ul` / `xuxie`）。
- 结构性命令直接操作编辑器（标题、列表、引用、代码块、表格、分割线、公式、Mermaid / PlantUML /
  ECharts / Vega-Lite / D2 / Graphviz / markmap）；AI 命令（续写 / 生成章节 / 总结 / 自定义指令）走
  `ai/start` + `ai/poll` 流式接口，结果插入光标处或文末，不进对话记录。
- 实现上不引入 `@tiptap/suggestion`：监听 `update` / `selectionUpdate` + 行首正则 `/^\/([\p{L}\p{N}_-]*)$/u`
  判定，用 `coordsAtPos` 定位浮动面板（含视口边界收敛）。

**编辑器顶部第二行（对齐 NoteGen 编辑器头部）**

- 左：笔记信息（文件名 / 目录 / 字数 / 行数 / 标题数），插入块（在光标处另起一行并输入 `/`，等同唤起命令面板）。
- 右：只读展示当前文件相对路径。

**同步配置（原 0.3.0 只有远端 + 三个按钮）**

- 代码托管选择：GitHub / GitLab / Gitee / Gitea，决定令牌拼接方式
  （`github → x-access-token`，其余 `oauth2`）。
- 访问令牌：只存本地 SQLite，回传只给 `hasToken` + 掩码（`前4••••后2`），支持「清除令牌」；
  写入后**只在推送时临时拼进 URL**，不写 `.git/config`（push 不再带 `-u`）。
- 自动提交开关、提交信息模板（支持 `{date}` / `{time}` / `{datetime}` 占位符）。

**同步通道：对象存储 / WebDAV / 自托管（补完原「未接入」三项）**

- 设置 → 同步的平台列表八项全部可用：本地 / GitHub / Gitee / GitLab / Gitea / 对象存储（S3）/ WebDAV / 自托管。
- 这四家 Git 平台仍走 `git`（令牌、提交模板、推送拉取）；后三家不走 Git，改为**文件镜像 + 清单**：
  工作区文件按相对路径写入 `<目录前缀>/files/<相对路径>`，另存 `<目录前缀>/manifest.json`
  记录每个文件的 `size / mtime / hash`（`hash` = `大小:SHA-1`，>8MB 退化为 `s:size:mtime`）。
- S3：复用图床那套 SigV4（GET / PUT / DELETE 全部签名），支持 AWS、Cloudflare R2、阿里云 OSS、
  腾讯云 COS、MinIO、Backblaze B2 与自定义端点，寻址方式可选 auto / path / virtual。
- WebDAV：PUT 前逐级 `MKCOL` 建目录（已建过的在本次会话内缓存，不重复请求），带 Basic 认证；
  连接检测用 `PROPFIND + Depth: 0`（缺 Depth 会被部分服务端按 infinity 拒绝）。
- 自托管：按「服务地址/目录前缀/files/相对路径」读写对象，可用 Bearer 令牌；服务端只需支持
  GET / PUT / DELETE。
- 增量与幂等：本地 `.dbx-note/sync-state.json` 记录「上次同步成功时的 hash」，据此判断改动来源——
  本地没动 → 拉取覆盖；远端没动 → 保留本地；两边都动 → 保留本地并列进 `conflicts`（下次 push 以本地为准）。
  重复 push 不会重复上传（`skipped` 计数），重复 pull 不会重复下载。
- push 默认不删除远端多余文件，勾选「上传时删除远端多余文件」才按本地做镜像。
- 密钥（Secret Access Key / WebDAV 密码 / 自托管令牌）只回传掩码 `前4••••后2` + `hasXxx` 标记，留空表示不修改。

**备份与恢复（设置 → 同步 下半部分）**

- 「立即备份」把整个工作区打包成 `zip` 存到 `<数据目录>/backups/dbx-note-<时间戳>.zip`；
  跳过 `.git`（可勾选包含）、跳过 >64MB 单文件，返回文件数与原始字节数。
- 备份列表：名称、体积、时间，逐条「恢复」「覆盖当前工作区」「删除」。
- 恢复默认解到 `<数据目录>/restore-<时间戳>`（不覆盖现场）；目标即当前工作区时必须显式 `overwrite=true`。
  解压用 `entry.enclosed_name()` 防目录穿越。
- 删除只允许 `backups/` 下的文件（canonicalize + `starts_with` 双重校验）。

**图片识别（多模态）**

- 图片预览弹窗新增「识别文字」：`ai/vision` 把图片（Sidecar 读盘 → `data:` URL，或前端传 base64）
  作为 `image_url` 消息发给 OpenAI 兼容接口；结果展示在图片下方，可「复制文字」或「插入笔记」。
- 使用「图片识别」独立配置（地址 / Key / 模型 / 提示词），未填则回落到 AI 模型配置。

**语音转写**

- `Ctrl/⌘ + M` 或「记录」面板的麦克风按钮打开语音弹窗：
  支持的宿主用 `MediaRecorder` 录音（带计时），否则走「选择音频文件」。
- 音频不落盘：`ai/transcribe` 新增 `audioBase64` + `mime` + `name` 分支，直接 `multipart` 上传到
  `/audio/transcriptions`；结果可编辑后插入笔记。
- 沙箱通常不给麦克风，弹窗会提示「当前宿主不允许直接录音，请选择音频文件」。

**图片存储规则**

- 设置 → 图片与语音：图片目录（默认 `assets`，做白名单化并拒绝 `..`）、命名规则三选一：
  随机 UUID / 日期时间 / 保留原文件名（自动加 6 位后缀防重名）。

**截图快捷键说明**

- 沙箱无法调用系统截图，设置页给出降级路径：系统截图（Windows `Win + Shift + S`，macOS `⇧⌘4`）
  → 编辑器内粘贴 → 自动落 `assets/` 并插入（0.3.0 已实现的粘贴链路）。
- **已被 8.18 / 8.23 取代**：抓屏改由 Sidecar 的 GDI 直接完成，截图成为带浮层的工具
  （框选、七种标注、复制 / 下载 / 插入笔记 / 保存到记录），不再需要先按系统截图再粘贴。

### 1.2 优化

- `editorBus` 增加 `openSlash`，并引入 `registerBus` 开关：并排对照的辅助编辑器不再注册，
  避免两个实例互相覆盖 / 后卸载者把主编辑器的能力清空（AI「插入到笔记」也受此保护）。
- `ai/transcribe` 的 mime 不再固定 `application/octet-stream`，按实际类型上传（部分服务会校验）。
- 同步令牌掩码按字符切分，粘贴非 ASCII 令牌不再可能切到 utf8 边界触发 panic。
- 图片 `saveImage()` 支持 `dir` / `nameMode` 选项，调用方按设置传入。

### 1.3 修复

- 并排对照关闭后「插入到笔记 / 大纲跳转 / 插入块」失效（`editorBus` 引用被辅助编辑器清空）。
- 斜杠面板 `Esc` 原先保留行首 `/`，现在一并删除，不留孤立斜杠。
- 语音弹窗文案曾缺失 `voice.*` 词条（显示原始 key），本版补齐。

| 方法 | 变化 |

## 5. 部署流程

```bash
npm ci
npm run typecheck
npm run backend        # 固定 GNU 工具链，产出 backend/target/release/backend.exe
npm run build          # 产出 ui/（单文件 bundle）
npm run pack:local     # 产出 release/com.mjj3610.note-0.4.0-windows-x64.dbxp
```

> 改了后端后必须重启开发宿主：宿主启动时拉起 Sidecar 子进程，旧进程不会热更新。

安装 / 升级：

1. DBX 中关闭「笔记」工作台。
2. 备份 `DBX_PLUGIN_DATA_DIR`（生产：`D:\Program Files\DBX\data\plugin-data\com.mjj3610.note`）。
3. 插件管理 → 从本地安装 → 选择 `com.mjj3610.note-0.4.0-windows-x64.dbxp`。
4. 自检：编辑器顶部出现第二行（信息 / 插入块图标）；空行输入 `/` 弹出命令面板；
   设置里出现「图片与语音」；设置 → 同步 出现托管平台、令牌、自动提交、提交信息模板与备份列表；
   `Ctrl/⌘ + M` 打开语音弹窗。

回滚：卸载 0.4.0 → 安装 0.3.0 `.dbxp` → 恢复数据目录备份（`backups/` 可保留）。

## 7. 已知问题与规避

1. **系统级全局热键仍不可用**：沙箱不允许注册全局热键，截图工具（8.23）需插件窗口在前台才能用
   `Alt + Shift + Z` 唤起；窗口外可先用系统截图（`Win + Shift + S`）再 `Ctrl+V` 粘贴。
2. **录音依赖宿主授权**：`getUserMedia` 在 `allow-scripts` 沙箱里通常被拒，弹窗会自动降级为「选择音频文件」；
   两条路径共用 `ai/transcribe`。
3. **图片识别 / 语音转写需模型支持**：分别要求多模态与 `/audio/transcriptions` 兼容接口（whisper-1、FunASR 等）；
   未配置时回落到 AI 模型配置，模型不支持会直接返回服务端错误。
4. **备份不增量**：每次全量 zip，工作区很大时耗时与磁盘占用线性增长；单文件 >64MB 会被跳过（返回里可对比 `files`）。
5. **恢复不合并**：解到新目录是默认行为，覆盖当前工作区需二次确认式的显式勾选，且不做三方合并。
6. **同步令牌安全边界**：令牌只存在于本地 SQLite 与调用参数里，不落 `.git/config`，但推送命令的 URL 会短暂出现在进程参数中（同机可见）。
7. **官方 CLI 打包需 MSVC**：与 0.3.0 相同，无 MSVC 时用 `npm run devhost` + `npm run pack:local`。
8. **对象存储 / WebDAV / 自托管是镜像同步**：只保证「按 hash 增量 + 冲突时保留本地」，
   没有三方合并，也没有版本历史；需要回滚请用 `backup/export` 的 zip。
9. **自托管需要服务端配合**：必须实现 `GET / PUT / DELETE` 三个对象接口，路径为
   `<服务地址>/<目录前缀>/files/<相对路径>`；不提供该接口的服务（如纯 NoteGen 服务端）无法直接对接。
10. **WebDAV 目录需可创建**：若服务端禁止 `MKCOL`（只读挂载），push 会在 PUT 阶段返回 4xx。

## 8. 0.4.0 补充：编辑器能力与同步策略对齐（同日追加）

本节记录同日追加的一批改动，`manifest.json` 版本号仍为 `0.4.0`，属同一版本的增量补齐。

### 8.1 颜色真正落进 Markdown

- 选中文字后气泡工具条新增「字体颜色」「高亮颜色」两枚六色板（红 / 橙 / 黄 / 绿 / 蓝 / 紫）与「清除格式」。
- 颜色不是只改 DOM：`src/lib/colorMarks.ts` 给两个 mark 注册了 `markdownTokenizer + parseMarkdown + renderMarkdown`，
  分别写回 `<span data-dbx-color="#…" style="color: …">` 与 `<mark data-dbx-color="#…">`；
  无色高亮退回 `==文本==`。tokenizer 用配对计数，支持嵌套同色内容，并跳过行内代码里的尖括号。
- 色值与参考实现同一组（`src/lib/textColors.ts`），只接受 `#rrggbb` / `rgb()`，其他值一律忽略。

### 8.2 公式（KaTeX / MathML）

- `src/lib/mathNodes.tsx`：行内 `$…$`、`\(…\)` 与块级 `$$…$$`、`\[…\]` 都是真实节点。
- 渲染走 `katex.renderToString(source, { output: 'mathml' })`：Chromium 原生渲染 MathML，**不需要** katex.css 与字体文件，
  在 `default-src 'none'` 的沙箱里不会被拦成错版。语法错误退化为纯文本 + `text-destructive`。
- 点击公式切到文本域编辑：`Enter` 提交、`Shift+Enter` 换行、`Esc` 取消。

### 8.3 图表（Mermaid）

- 依赖 `mermaid ^11.12.2`（与参考实现同版本）。`src/lib/mermaidNode.tsx` 定义 `mermaidDiagram` 节点：
  实时渲染 SVG、点击改源码、可切图类型、空图表直接进编辑态。
- 斜杠菜单「图表」分类改为与参考实现一一对应的 8 种 Mermaid 图
  （流程图 / 时序图 / 甘特图 / 类图 / 状态图 / 饼图 / ER 图 / 旅程图），插入的是节点而不是一段代码文本。
- 渲染串行排队（mermaid 内部有全局状态，并发 render 会串图）；主题跟随界面深浅色，
  用 MutationObserver 监听 `html` 的 `class` / `data-appearance` / `data-dbx-theme` 后重画。

### 8.11 颜色面板定位修正（气泡工具条内）

**问题**：选中文字后点气泡工具条上的字体颜色 / 高亮颜色，下拉面板跑到文档左上角、甚至超出编辑器。

  面板留在里面会跟着消失。

### 8.18 系统能力下沉到 Sidecar：截屏 / 剪贴板 / 录音

| 能力 | RPC | 实现 |
| --- | --- | --- |

### 8.20 图片预览缓存：消除沙箱内 404

### 8.21 插入节点看不见 / 占位文案漏 key

补完 e2e 截图断言后暴露的三个真实缺陷：

1. **插入后节点跑到视野外**：`insertAtCenter` 遇到重叠会一直往下推（最多 40 格 × (h+32)），
   180% 缩放下插一张图片能被推到 8000 多像素之外，用户看到的就是「点了没反应」。

### 8.24 截图框选改到真实桌面：全局热键 + 1:1 无缩放

本轮把框选这一段整体搬到 Sidecar 的原生窗口，插件浮层退回「标注台」的角色。

**新增 `backend/src/screenshot.rs`（约 520 行）**

| 步骤 | 实现 |
| --- | --- |
| 抓图 | `virtual_screen()`：GDI `BitBlt` 抓**虚拟桌面**（所有显示器拼成的整块区域，原点可为负），DPI 感知下拿到物理像素 |
| 建窗 | `WS_POPUP` + `WS_EX_TOPMOST`/`WS_EX_TOOLWINDOW` 无边框窗口，位置尺寸 = 虚拟桌面，即整块桌面 |
| 绘制 | 底图先画一遍**压暗版**（逐像素 ×43%），选区再叠回原亮度 —— 等价于「选区外半透明遮罩」，但不需要 `AlphaBlend`；边框 `FrameRect` + 左上角 `TextOutW` 显示 `宽 × 高` |
| 交互 | `WM_LBUTTONDOWN` 起框、`WM_MOUSEMOVE` 实时重绘、`WM_LBUTTONUP` 定稿（拖不满 3px 视为取消）；`Esc` / 右键取消；`SetCapture` 保证拖出窗口也能收到 |
| 收尾 | 销毁窗口前记下前台窗口，`PostQuitMessage` 退出模态循环后 `SetForegroundWindow` 还回去，插件浮层不会落到别的窗口后面 |
| 裁剪 | 按选区从 BGRA 整屏里逐行拷出来，转回 RGBA，再走既有 PNG 编码 |

关键点：**没有任何缩放**。窗口按物理像素铺满桌面，画的是 1:1 原图，鼠标坐标直接就是图像坐标，
所以 1920×1080 屏上拉 420×280 的框，拿到的就是 420×280 的真实像素。

**全局热键**

- Sidecar 启动时用 `RegisterHotKey` 注册，独立线程跑消息循环，插件不在前台也能唤起框选。
- 候选链 `Alt+Shift+Z → Ctrl+Alt+Z → Alt+Shift+X → Alt+Shift+D → Ctrl+Alt+Shift+Z`，
  注册到哪个用哪个。实测本机 `Alt+Shift+Z` 已被占用（宿主或别的软件），最终生效 `Ctrl+Alt+Z`；
  实际组合通过 `screenshot/hotkey` 报给设置页展示，不再让人猜。
- 全局按下时：框选完 → 直接写系统剪贴板（`clipboard/write`）→ 同时留一份**挂起项**。
  回到插件窗口时，聚焦轮询（1.2s + `focus` / `visibilitychange`）把挂起项取出来继续标注 / 存记录。
  这跟 Windows 自带截图（选中即进剪贴板）的语义一致，也不会让用户觉得「按了没反应」。
- 双触发防护：插件内按同一个键时，前端也会调 `screenshot/select`。热键线程命中后先等 80ms，
  若此时已有 RPC 进来（`mark_rpc` 时间戳在 600ms 内）或框选窗口已打开，就让给前端，不弹两个窗口。

**顺带修掉一个真实缺陷**：`App.tsx` 的全局快捷键处理第一行是
`const meta = event.metaKey || event.ctrlKey; if (!meta) return`，而默认截图绑定是

e2e 加了一条真实按键断言（把绑定临时改成 `Alt+Shift+F7` 再按下去，浮层必须出现）。

### 8.25 截图小图工具栏不遮挡 + 保存到记录自动调用图像识别

反馈两件事：① 截图较小时工具栏被挤压 / 挡住（参考项目里工具栏正常）；② 截图发送到记录
应该调用图像识别模型解读图片，而不是只存一张缩略图。本轮一起修。

**一、工具栏改成视口级定位**

原先工具条是图片容器的绝对定位子元素（`absolute` + `max-w-full` + `overflow-x-auto`），
图片容器在图片缩得比工具条还窄时，工具条就被容器宽度裁掉、挤出一条横向滚动条，按钮看不全。

改成 `position: fixed` + 视口坐标：

- 用 `ResizeObserver` + 窗口 resize 量出画布在窗口里的实际位置（`canvasBox`），选区坐标加这个
  偏移换算到视口。
- 宽度不再受图片容器约束，改成 `maxWidth = min(估计宽, innerWidth - 24)`；高度不足时向上翻，
  再不够就贴窗口底部，绝不压在图片上。
- 无选区时贴窗口底部居中，有选区时优先贴选区下方、其次上方。
- 浮层容器加 `overflow-hidden p-6`，避免画布在窄窗口下把整个页面撑出滚动条。

实测（窗口 1280×800）：

| 选区 | 画布 | 工具条 | 结果 |
| --- | --- | --- | --- |
| 829×356 | y=222, h=356 | y=588, 宽 560 | 在图片下方、不遮挡、窗口内完整 |
| 300×180 | y=310, h=180 | y=500, 宽 560 | 同上 |

`overlapsImage` 均为 false，工具条完整无滚动条。

**二、保存到记录时自动识别图片**

`src/lib/screenshot.ts` 新增 `saveShotToRecords()`：

- 落库与识别拆成两步：先 `record/create`（`type: 'image'`，`content` 存图片路径，`meta` 带
  `{ name, source: 'screenshot' }`）让「已保存到记录」立即有反馈；
- 再异步 `describeRecordImage()` 调 `ai/vision`，识别结果写进 `meta.text`。

识别配置与图片预览弹窗的「识别文字」完全共用：`ocr.baseUrl/model` 为空时退回 `ai.*`；
设置里「图片识别」总开关（`imageMethod.enabled`）关掉就不打扰用户；识别失败只 console.warn，
**不影响记录本身**（记录不会因为模型没配 / 报错变成错误状态）。

识别用的提示词（用户没自定义时）：`描述这张图片的内容与用途，并原样提取图中的关键文字；用简洁的中文输出，不要寒暄。`
——因为「保存到记录」的语义是「看图 + 抽文字」，跟预览弹窗里默认的纯 OCR 略有不同，所以分开给了默认提示词。

`RecordPanel.tsx`：图片记录在缩略图下方展示 `meta.text`（`data-record-insight`），`line-clamp-3`
限制高度，不把记录列表撑爆。

**后端**：`record_list` 的关键词过滤从只查 `content` 改成同时查 `meta`（
`(lower(r.content) LIKE ? OR lower(r.meta) LIKE ?)`），这样识别出来的文字也能被「记录搜索」命中。

### 8.27 截图选区偏移加固 + 全局热键离开笔记失效修复

用户反馈两个问题：① 桌面框选的区域与实际截到的区域有偏移；② 只能在笔记编辑器里截图，
离开笔记（插件不在前台）后按快捷键没反应。

**问题②（全局热键失效）——三个叠加根因，全部修复：**

1. **热键线程的让位判断误伤**（`backend/src/screenshot.rs`）：老实现用「最近 600ms 内
   有任何 RPC」判断「这次按键是插件自己在处理」。宿主心跳、前端后台轮询等**任何** RPC
   都会刷新这个时间戳 → 插件不在前台时全局热键被永久压制。改为精确标记：新增
   `screenshot/uiHotkey` RPC，前端快捷键 keydown 命中时先打标记（`App.tsx` 的
   `app.screenshot` 分支），热键线程只认这个标记 + `SELECTING` 标志（等 150ms 让标记先到）。
2. **`DBX_NOTE_SHOT_HOTKEY=off` 实际没关闭注册**（`backend/src/main.rs`）：老代码 filter
   掉 `off` 后传 `None` 给 `start_hotkey`，而 `None` 走完整候选链 → 每个测试 devhost
   都在开发机上注册 `Alt+Shift+Z`。生产宿主的 Sidecar 注册不上默认组合，只能落到
   冷门备选（用户不知道、按了没反应）。实测中用户按 Alt+Shift+Z 时，响应的是**残留
   devhost 后端**（其日志里留下「全局截图失败：已取消截图」），截图进了无人轮询的挂起
   队列。现在 `off` 完全不注册，未设置才走候选链。
3. **环境治理**：e2e / smoke 的 devhost 改用 `DBX_NOTE_SHOT_HOTKEY=Ctrl+Alt+F9`（冷门

### 8.28 折叠按钮常显 / 截图结果预览窗 / 框选实时重绘 / 行内公式示例

用户反馈四项：① 标题折叠标识太隐蔽；② 在别的应用或桌面上框选后**看不到任何结果**，
得切回 DBX 点一下编辑器才弹出标注浮层；③ 框选拖拽调整大小时，选区里的画面**不跟着变**，
一直停在某一部分内容；④ 行内公式编辑态没有「常用公式」提示（块级弹窗有）。

#### ① 折叠按钮：从 hover 才出现改成常显 + 状态高亮

`src/lib/headingFold.ts`：原先按钮 `opacity-0`、靠 `group-hover:opacity-100` 才显形，
触屏和第一次用的用户根本不知道该点哪儿。现在：

- **常显小胶囊**：`size-5` 圆角按钮 + 实边框 `border` + `bg-background` + `shadow-sm` +
  `text-foreground/65`（不再靠透明度压到几乎看不见），hover 才加深；
- **箭头图标**换成内联 SVG（`M4 6.5l4 4 4-4`，`stroke-width` 1.9），折叠时
  `transform: rotate(-90deg)`（▾ → ▸），比原来 12px 的字符箭头更清楚；
- **折叠态换主题色**：`border-primary/60` + `bg-primary/10` + `text-primary` +
  `opacity-100`，一眼能看出「这里藏着内容」；
- **标题行右侧留位** `pr-8`，长标题不会压住按钮；
- 补 `aria-label` / `aria-expanded`（`true` / `false`），键盘与读屏可用。

#### ② 全局截图结果看不到：轮询放宽 + Sidecar 结果预览窗

两个独立原因，都修了：

1. **前端轮询被焦点条件挡住**（`src/App.tsx`）：`pollPendingShot` 原先要求
   `document.hasFocus()`。插件不在前台（用户正在别的应用里框选）时这个条件不成立 →
   挂起项一直没人取，必须切回 DBX 并点一下编辑器拿到焦点才弹出。
   改为只判断 `document.visibilityState === 'visible'`；挂起项本身只有 2 分钟有效期，
   放宽是安全的（过期就丢，不会误弹旧图）。
2. **切回前没有任何反馈**（`backend/src/screenshot.rs` 新增 `mod preview`）：
   热键路径在 `capture_to_clipboard()` 末尾另起线程弹一个结果预览窗，告诉用户「截到了」。
   - 样式：`WS_POPUP` + `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`
     （置顶、不进 Alt+Tab、**不抢焦点**，不打断用户正在别的应用里的输入）；
   - 位置：工作区右下角（`SystemParametersInfoW(SPI_GETWORKAREA)`）内缩 16px；
   - 内容：缩略图（等比缩到 ≤480×320，最近邻）水平居中 + 底部 30px 提示条
     「已复制到剪贴板 · 回到 DBX 可继续标注（W × H）」，脚注报的是**原始截取尺寸**
     （缩略图会缩小，早期版本误报了缩略图尺寸，已改为单独存 `source_w/source_h`）；
   - 行为：6 秒 `SetTimer` 自动关、左键点击即关；字体显式用 `Microsoft YaHei`
     （GDI 中文链接不稳），取不到退回 `DEFAULT_GUI_FONT`。

#### ③ 框选拖拽不实时：改成脏矩形局部重绘

根因在 `WM_PAINT`：旧实现在每次重绘里都整窗 `StretchDIBits` 两遍（压暗底图 + 选区内亮图），
1080p 下每帧约 400 万像素，而每次 `WM_MOUSEMOVE` 又都 `InvalidateRect(hwnd, null, 0)`
把整窗标脏 → 快速拖拽时重绘追不上输入，消息队列积压，画面就停在某一帧上（用户看到的
「一直是某一部分选择内容」）。

现在：

- `WM_MOUSEMOVE` 只算「旧选区 ∪ 新选区」两块带，`invalidate_band()` 分别
  `InvalidateRect`（各向外扩 `-6,-30,+6,+6`，把边框和左上角尺寸角标一起覆盖）；
- `paint()` 只按 `ps.rcPaint` 画：DIB 是自顶向下 `BI_RGB`、目标与源坐标一致，
  所以局部重绘的目标矩形与源矩形都用 `rcPaint`；选区内亮图只画与失效区相交的部分。

#### ④ 行内公式：补常用公式示例（与块级共用清单）

- 新增 `src/lib/mathExamples.ts`，把八个示例（分数 / 上标 / 下标 / 平方根 / 求和 /
  积分 / 极限 / 希腊字母）抽成共享常量，`BlockMathDialog` 与行内编辑态都引它，
  避免两处清单跑偏；
- `src/lib/mathNodes.tsx` 的 `MathEditor` 在输入框下方渲染「常用公式」一行 chips，
  点击把 LaTeX **插到光标处**（有选中内容则替换），随后回焦并把光标停在插入末尾；

### 8.29 全局截图接回标注工具栏 + 框选拖拽按差分条带重绘

#### ① 全局截图接回「可标注的浮层」

三层原因，逐一堵住：

1. **前端轮询被门槛挡住**（`src/App.tsx`）：上一轮已把 `document.hasFocus()` 放宽成
   `visibilityState === 'visible'`，但插件跑在 iframe 里——面板被折叠 / 宿组切走 / 刚切回
   宿主时都可能判成不可见；更隐蔽的是**隐藏页面里的 `setInterval` 会被浏览器节流到分钟级**，
   所以「等一会儿自己出来」根本不成立。现在：去掉可见性门槛，间隔 700ms，并补
   `focus` / `visibilitychange` / `pointerdown` 三个立即触发点（用户一动就补一次）。
2. **宿主还在后台，浮层在后台窗口里**：即使取到图，用户也看不见工具栏。Sidecar 截完图后
   主动把宿主主窗口激活到前台——`native::focus_host_window()`：用 ToolHelp 沿父进程链
   往上找 3 层（Sidecar 是宿主拉起的），`EnumWindows` 命中「可见、无 owner、标题非空」的
   顶层窗口（无标题的辅助进程/控制台跳过，继续往上找），再 `IsIconic → SW_RESTORE` +
   `SW_SHOW` + `SetForegroundWindow`；被前台锁拒绝时 `AttachThreadInput` 挂到前台线程 +
   `BringWindowToTop` 重试。找不到宿主窗口（如 devhost 场景）就静默跳过，不阻塞截图。
3. **兜底不变**：图仍然同时进系统剪贴板，右下角结果预览窗照旧弹 6 秒。只想拿图时
   按 `Esc` 关掉浮层即可，不会打断「复制到别处」的用法。

上一轮把整窗重绘改成了局部重绘，但**每帧仍然把「旧选区整块 ∪ 新选区整块」都标脏**：
选区一大（1500×800）每帧还是 ~100 万像素画两遍；而且 `WM_PAINT` 是异步的，快速拖动时
重绘请求排队，越拖越落后。用户看到的正是「锚点那条边不动（看着正常），正在移动的
那条边一直落在鼠标后面」——从下边拖就是「上边跟随、下边不跟随」。

### 8.30 Sidecar 日志落文件 + 设置 → 关于 里可直接查看

用户问「Sidecar 日志在哪里看」——之前**根本无处可看**：Sidecar 只把诊断写 stderr，
而宿主把子进程的 stderr 收进自己的日志里，普通用户既不知道路径也没有入口。截图类问题
（热键没反应 / 宿主没前置 / 框选窗口没出来）只能靠现象猜。

**落文件**（新增 `backend/src/logs.rs`）：

- 位置：`<数据目录>/logs/sidecar.log`。数据目录由宿主通过 `DBX_PLUGIN_DATA_DIR` 提供，
  没有则退回 `%APPDATA%\dbx-note`（设置 → 关于 里的「数据目录」就是它）。
- 每行带毫秒时间戳：`2026-11-04 05:31:55.351 [dbx-note] Sidecar 启动 · pid=… · version=…`。
- 启动时若文件超过 1 MB，轮转一份 `sidecar.log.1`（只留一代，不会无限长大）。
- 写入串行化（`Mutex`），截图线程与 RPC 线程同时写也不会半行交错。

**统一输出**：新增 `crate::logln!` 宏 —— 一次调用同时写 stderr（devhost / 宿主日志照旧可看）

### 8.32 全局截图浮层「花屏」+ 工具栏消失

用户回帖（附屏幕照片）：

```

2026-11-04 07:36:32.837 [ui] 取到挂起截图 1001×425，打开标注浮层
```

日志证明**接回链路是通的**（浮层由页面自己打开），但照片里浮层的画面是**斜向阶梯条纹**
（密集小字被采成一层层台阶，用户描述为「花屏」），并且**看不到工具栏**。

#### 定位过程

| 排查 | 结论 |
| --- | --- |
| 后端出图 | 用 `DBX_NOTE_SCREENSHOT_AUTO=40,40,1001,425` 造奇数宽度区域，`screenshot/select` 拿到的 PNG 用 `ViewImage` 逐块核对——**完全清晰，无花屏**。后端（GDI 抓屏 / 裁剪 / PNG 编码）无责 |
| 宿主装的 UI | `data/plugins/com.mjj3610.note/versions/0.4.0/ui/assets/index-DmB0IqXX.js` 与本机构建产物同名同内容，跑的就是当前代码，不是旧包 |
| 纯浏览器复现 | 同一张 1001×425 奇数图，1280×720 / 480×700 两种视口 × dpr 1 / 1.25 × headless（软件光栅）/ 有头（GPU）四种组合，`canvas.toDataURL()` 取回画布内容逐次目视——**全部正常，工具栏也在** |
| 环境差异 | 宿主显示器 100% 缩放（`diag_drag` 报 `dpi=96 scale=1.00`），dpr=1，与复现条件一致；差异只剩**宿主是 WebView2** |

照片里花屏区四周是**无特征深灰**（不是被压暗的界面内容）——正是浮层
`bg-black/80 + backdrop-blur-sm` 把背后内容糊成一片的效果，说明花屏就发生在浮层的 canvas 里。

#### ① 「花屏」：大比例缩小被 GPU 重采样采坏

浮层把原图交给 `drawImage` 直接压到面板宽度：1001 px 宽压到 430 px 左右是 **2.3 倍缩小**。
这种比例下浏览器默认走 `imageSmoothingQuality = 'low'` 的缩放路径，密集小字会被采成
摩尔纹 / 阶梯状斜条（正是照片里的形态）；WebView2 的合成层再叠一层 `backdrop-filter`，
就把不稳定的采样结果固化在屏幕上了。

改法（`src/components/dialogs/ScreenshotOverlay.tsx` + `src/lib/screenshotEditor.ts`）：

1. **缩放交给解码器**：新增 `sample` 状态，用
   `createImageBitmap(blob, { resizeWidth, resizeHeight, resizeQuality: 'high' })`
   在解码阶段按「画布后备像素」缩好（`resizeQuality: 'high'` 是高阶重采样，不是 low 的双线性）；
2. **画布 1:1 贴图**：`paintScene` 改为接收 `CanvasImageSource`，位图按 CSS 尺寸画进去，
   因为位图本身就是 `round(viewport × dpr)`，缩放矩阵 `dpr` 之后正好是 **1:1**，
   不再有任何二次重采样；
3. **后备像素取整一致**：`canvas.width = max(1, round(viewport.width × dpr))`，
   CSS 尺寸仍是 `viewport`，不留半像素误差；
4. `imageSmoothingQuality = 'high'` 显式设置，兜底路径（`createImageBitmap` 不可用）也不再走 low；
5. **去掉 `backdrop-blur-sm`**：浮层改为不透明 `bg-neutral-950/95`。它既非必要
   （背后是被全屏遮住的界面），又会给整个浮层引入一层合成上下文——`position: fixed`
   的后代还会把它当成包含块，是工具栏消失的隐患之一。

#### ② 工具栏消失：`fixed` + 视口坐标这条路不成立

工具条原来用 `position: fixed` 加「用 `getBoundingClientRect()` 量出画布位置再算
上下左右」，依赖宿主把视口尺寸、滚动、合成层都报准。这条链路已经连续两轮出问题
（8.29「完全没有工具栏」、本轮「工具栏不见了」），本轮直接换成**结构上不可能丢**的做法：

- 工具条改成浮层里普通流的一个 flex 子项，紧跟在图片容器后面：
  `flex flex-col` 根容器 + `gap-3`，图片在上、工具条在下；
- 删掉 `canvasBox` 状态、`ResizeObserver` 测量、`barStyle` 计算（约 35 行），
  位置完全由布局决定，任何窗口尺寸 / 缩放 / 合成方式都跑不掉；
- 窄面板下 `overflow-x-auto` + `max-w-full` 自己横向滚动，不会撑破浮层也不会被裁掉；
- 视觉上仍然固定在图片正下方（用户要的就是「下方的工具栏」）。

#### ③ 加一行几何日志，下次可自证

### 8.34 全局截图改为「桌面就地标注」：工具栏与笔记里那套完全一致

#### 现象（用户反馈，8.33 的直接后果）

8.33 撤回原生标注窗后，全局热键变成了「框选 → 图直接进剪贴板 → 跳回 DBX 弹预览浮窗 →
在宿主里标注」。用户明确否掉这个走向：

- 「应该是全局截图的工具栏与在 dbx 内截图的工具栏一样」；
- 「所有截图应该在全局截图时**直接带工具栏**进行标注，确认后再进入记录 / 复制 / 进入笔记，
  而不是直接到了剪贴器并显示一个浮窗，也不是要切换到 dbx 中才能标注」；
- 「全局截图不能出现花屏图」。

#### 根因

不是"原生窗做不了"，而是**上一版原生窗自造了一套 UI**：深色条 + 工具名文字 + 复制/完成/取消，
和浮层的图标式工具栏（七工具 + 四色 + 四档粗细 + 撤销/重做 + 复制/插入笔记/保存到记录）不是一套。
用户看到的"两套 UI"其实是"工具栏内容不同"，不是"位置不同"。

#### 做法：同一个窗口，两个阶段

#### 现象（用户反馈）

| --- | --- | --- |

#### 根因

**③④⑤ 三条各有一个根因，其余是复核项：**

- **`COLORREF` 通道顺序反了**。GDI 的 `COLORREF` 是 `0x00BBGGRR`，代码把 `0xRRGGBB`
  直接塞进去，于是 `#ef4444` 画成蓝色、`#ffffff` 画成黑色。这不是"配色不对"，
  是**每一颗颜色点都错位**，所以截图里红橙黄绿蓝紫全乱，白点变黑点。
- **主按钮宽度是估出来的**。原来用 `text_w()` 按"13px × 字数 + 26px 余量"算，
  「保存到记录」五个全角字实际占 60px 而估成 65px 减去 padding 后不够，
  `DrawTextW` 又带 `DT_END_ELLIPSIS`，就直接裁成「存到记」。
- **存记录只走了本地**。参考项目的链路是 `processSavedScreenshot()`
  **三步互不阻塞**：先本地落库让记录立刻可见 → 异步识别写 `meta.text` →
  异步上传图床把 `content` 换成远端 `url`。本插件原来只有第一步。

#### 做法一：颜色走 `cref()`，一次性修掉所有错位

新增 `const fn cref(rgb: u32) -> u32`，把 `#rrggbb` 换成 `0x00BBGGRR`，
所有色常量都过一遍：

```rust
const fn cref(rgb: u32) -> u32 {
    ((rgb & 0x0000_00ff) << 16) | (rgb & 0x0000_ff00) | ((rgb >> 16) & 0x0000_00ff)
}
const CARD_BG:    u32 = cref(0xff_ffff);
const CARD_EDGE:  u32 = cref(0xe5_e7eb);
const HOVER_BG:   u32 = cref(0xf4_f4f5);
const ACTIVE_BG:  u32 = cref(0xe8_e8ea);   // 选中工具/色点的灰底
const ICON:       u32 = cref(0x18_181b);
const ICON_OFF:   u32 = cref(0xd4_d4d8);   // 撤销/重做禁用态
const PRIMARY_BG: u32 = cref(0x18_181b);   // 黑色主按钮
const PRIMARY_FG: u32 = cref(0xfa_fafa);
const TRACK_BG:   u32 = cref(0xf4_f4f5);
const THUMB_EDGE: u32 = cref(0x18_181b);
const SWATCH_EDGE:u32 = cref(0xe5_e5e5);
const TEXT_MUTED: u32 = cref(0x52_525b);
const BADGE_BG:   u32 = cref(0xf4_f4f5);
const FRAME:      u32 = cref(0x18_181b);
```

验证方式是把工具栏截下来统计颜色直方图，与参考项目 `COLORS` 常量逐个比对：

```
0xef4444  0xf97316  0xfacc15  0x22c55e  0x3b82f6  0xa855f7  0xffffff  0x171717
```

八个色块全部命中且顺序一致，白点不再是黑点。

#### 做法二：主按钮宽度按真实文本量算

去掉估算，改成"全角算一个字宽、半角算 0.6 个字宽"，再按参考项目的
`px-3 + icon + gap-1.5 + text + px-3` 结构精确求和：

```rust
const PRIMARY_LABEL: &str = "保存到记录";
const PRIMARY_FONT: i32 = 12;
const PILL_PAD_X: i32 = 12;
const PILL_ICON: i32 = 15;
const PILL_GAP: i32 = 6;

fn label_w(label: &str, size: i32) -> i32 {
    label.chars().map(|ch| if (ch as u32) < 0x2e80 { size * 6 / 10 } else { size }).sum()
}
fn primary_w(scale: f64) -> i32 {
    let base = PILL_PAD_X * 2 + PILL_ICON + PILL_GAP + label_w(PRIMARY_LABEL, PRIMARY_FONT);
    (base as f64 * scale).round() as i32
}
```

绘制改成左对齐（对勾图标在左、文字紧跟），不再用 `DT_END_ELLIPSIS`：

```rust
Action::Record => {
    fill_round(hdc, &area, s(6), PRIMARY_BG);
    let cy = (area.top + area.bottom) / 2;
    let pad = s(PILL_PAD_X);
    let side = s(PILL_ICON);
    let check = RECT { left: area.left + pad, top: cy - side / 2,
                       right: area.left + pad + side, bottom: cy + side / 2 };
    draw_check(hdc, &check, PRIMARY_FG);
    let text = RECT { left: check.right + s(PILL_GAP), top: area.top,
                      right: area.right - pad, bottom: area.bottom };
    draw_text(hdc, &text, PRIMARY_LABEL, s(PRIMARY_FONT), PRIMARY_FG, false);
}
```

#### 做法四：修复标注阶段看不到 8 个选区手柄

`enter_annotate()` 没清 `state.anchor`，而 paint 里判断手柄的条件是
`anchor.is_none()`（语义是"已经松手、不再拖选区"）。框选结束后锚点还留着，
于是手柄被一直藏起来。补一行清锚点即可：

```rust
STATE.with(|cell| {
    if let Some(state) = cell.borrow_mut().as_mut() {
        state.ink = Some(ink);
        state.bar = Some(bar);
        state.scale = scale;
        // 框选已经结束：清掉锚点，`anchor.is_some()` 就是「还在拖选区」，
        // 只剩它才会藏手柄。不清的话标注阶段永远看不到那 8 个手柄。
        state.anchor = None;
    }
});
```

实测标注阶段八个白底方框手柄全部回归（`white 100+ / frame 42+` 像素），
选区左上角 `500 × 350` 尺寸角标正常。

#### 做法五：探针改实时，撤销/重做后工具栏跟着重绘

原来 `store_probe_annotate` 只在进场时写一次，`colors`/`widths` 是写死常量，
换工具后探针读到的还是旧档位。抽出 `refresh_probe_annotate()`，
在 `enter_annotate` 末尾、`handle_action` 的 `relayout` / `bar_dirty` 分支、
`WM_LBUTTONUP` 提交形状之后各调一次，全部重算：

```rust
"tool": format!("{:?}", ink.tool),      // 当前工具
"colors": colors,                        // 当前是否显示色点（0 / 8）
"widthTrack": widths,                    // 当前是否显示滑轨
"widths": [WIDTH_MIN, WIDTH_MAX],        // [1, 12]
"stroke": ink.stroke,
"canUndo": ink.can_undo(),
"canRedo": ink.can_redo(),
```

实测：`select → 卡片高 52 / colors 0`、`mosaic → 高 96 / colors 0`、
`text|rect → 高 96 / colors 8`。

同时 `Action::Undo` / `Action::Redo` 补 `bar_dirty = true`——撤销按钮从灰色亮起来
需要重绘工具栏，只刷画布看不到变化：

```rust

#### 做法七：「保存到记录」= 本地落库 → 图像识别 → 图床上传

这是本节的主体改动，对齐参考项目 `desktop-screenshot-bridge.tsx` 的
`processSavedScreenshot()`：**三步互不阻塞，任何一步失败都不影响前一步的成果**。

`src/lib/screenshot.ts` 重写 `saveShotToRecords()`：

```ts
export async function saveShotToRecords(
  dataBase64: string, mime = 'image/png',
): Promise<{ src: string; recordId: string }> {
  const name = stampName(mime)
  const settings = useSettingsStore.getState()

  // 1) 本地落盘。刻意不走 `persistImage`：那条路径在图床模式下会跳过本地，
  //    万一图床挂了就一张图都不剩。存记录必须先把图钉在本地。
  const local = await rpc.saveImage(name, dataBase64, {
    dir: settings.image.dir, nameMode: settings.image.nameMode,
  })
  rememberPreview(local.path, `data:${mime};base64,${dataBase64}`)
  const record = await rpc.createRecord({
    type: 'image', content: local.path,
    meta: { name, source: 'screenshot' },
  })
  await useRecordsStore.getState().load()   // 记录立刻可见
  void rpc.logWrite(`截图已存记录：本地 ${local.path} · 图床=${settings.imageHosting?.provider ?? 'local'}`).catch(() => {})

  // 2) 3) 识别与图床并行推进，谁先好谁先写
  void describeRecordImage(record.id, dataBase64, mime)
  void hostRecordImage(record.id, name, dataBase64, mime)

  return { src: local.path, recordId: record.id }
}
```

**识别**（`describeRecordImage`）：先写占位 `meta.text = 「正在识别图片…」`，
拿到结果写真实 OCR/描述文本，空结果写「没识别到可用文字」，异常写「图片识别失败」。
`meta` 是**合并写**，不会覆盖 `name` / `source`。

**图床**（`hostRecordImage`）：`provider === 'local'` 直接返回；否则
`rpc.imageUpload({ name, dataBase64, mime, config: hosting })` 拿远端 `url`，
成功后 `rpc.updateRecord({ id, content: url, meta: { …, hosted: true, provider } })`
把记录内容换成远端地址；**失败只记一行日志、保留本地图**，不抛错给用户。

#### 做法八：预览支持远端图床地址

#### 做法九：`grab_rect` 加重试，修掉偶发「截屏失败」

显示器刚被唤醒（DPMS 关闭 / 远程会话刚连上）时，第一次 `BitBlt` 会返回 0。
原来直接报错，用户按热键就吃到「截屏失败」。改成最多 3 次、每次间隔 90ms：

```rust
unsafe fn grab_rect(x: i32, y: i32, width: i32, height: i32) -> Result<Vec<u8>, String> {
    let mut last = String::new();
    for attempt in 0..3 {
        match grab_rect_once(x, y, width, height) {
            Ok(pixels) => return Ok(pixels),
            Err(message) => {
                last = message;
                if attempt < 2 { std::thread::sleep(std::time::Duration::from_millis(90)); }
            }
        }
    }
    Err(last)
}
```

之后 `screenshot/globalShot` 稳定返回 `{ exit: "record", ok: true }`，
探针 `painted: 1 / barInsideWindow: true / buttons: 23`。

### 8.36 工具栏复刻参考项目视觉规格 + 截图稳定性加固 + 像素级自检探针

8.35 把工具栏的**结构**（工具数、色点数、滑轨档位、快捷键）对齐了，但**视觉**仍是"自己画的示意图"：
图标是填充多边形、卡片没有投影、主按钮尺寸和配色都不是参考项目那一套。本节把视觉规格逐项落到
`note-gen v0.39.2` 的 Tailwind 类值上，并给截图链路补上"能不能用机器证明没画错"的能力。

#### 现象（用户反馈）

| 编号 | 现象 | 本轮处理 |
| --- | --- | --- |
| ① | 拖拽框选过程中，选区里出现了"框住的区域没有的内容" | 加像素级探针取证；修掉两处可能导致"残留上一帧"的路径 |
| ② | 截图工具栏与参考项目样式风格差距较大 | 本节主体：图标 / 投影 / 主按钮 / 配色全部重做 |
| ③ | 截图稳定性不足（偶发失败、偶发全黑） | `grab_rect` 重试 + 全黑检测 + 明确报错 |

#### 根因

**② 是"没照规格做"，①③ 是"没有证据链"。**

- **图标不是 Lucide**。参考项目用 `lucide-react`，24 视口、`stroke-width: 2`、圆头圆角、**描边不填充**；
  本插件原来用 `Polygon` 填充一坨近似形状，16px 下要么糊成一团、要么轮廓和参考项目根本不是同一个东西。
- **卡片没有投影**。参考项目是 `shadow-xl`（两层：`0 20px 25px -5px` / `0 8px 10px -6px`，各 10%），
  卡片浮在压暗的背景上靠的就是这层投影；没有投影，卡片和背景之间"贴"在一起。
- **主按钮规格不对**。参考项目是 `<Button>` 默认档 `h-9 px-4 text-sm gap-2 [&_svg]:size-4`；
  原来字号、内边距、图标尺寸、间距四项全小于规格，视觉上明显"瘦一圈"。
- **禁用态看不见**。参考项目是 `disabled:opacity-50`（黑图标降到 50% ≈ `#8b8b8d`），
  原来用 `#d4d4d8`，白底上几乎不可见，撤销/重做像"没这两个按钮"。
- **① 的两个可疑点**（不是"内容错了"，而是"上一帧没被覆盖"）：
  - `StretchDIBits` 在**源和目标同尺寸**时，部分显卡驱动仍会走缩放器，可能偏一格或重采样；
  - `back_buffer()` 建不出来时原来直接 `return`，本帧**整块不画**，屏幕上留着上一次的窗口内容——
    拖拽时肉眼看到的就是"这块区域显示的还是刚才那张图"。
- **③ 是时序问题**。显示器刚被 DPMS 唤醒 / 远程会话刚连上时，首次 `BitBlt` 会返回 0；
  锁屏或处于安全桌面时 `BitBlt` **会成功但抓到一整屏黑**，原来直接把黑图当截图结果返回。

#### 做法一：图标系统重写成 Lucide 24 视口描边

不引图标字体、不带位图资源，直接把 Lucide 的路径点按 24 视口写死，再用 GDI 的**几何钢笔**描出来：

```rust
const ICON_SIZE: i32 = 16;      // 参考项目 [&_svg]:size-4
const ICON_VIEW: f64 = 24.0;    // Lucide viewBox

struct IconCtx {
    hdc: HDC,
    left: i32, top: i32, size: i32,
    pen: HPEN, old_pen: HGDIOBJ, old_brush: HGDIOBJ,
}

impl IconCtx {
    fn new(hdc: HDC, area: &RECT, tone: u32, scale: f64, weight: f64) -> Self {
        let size = ((ICON_SIZE as f64) * scale).round().max(1.0) as i32;
        let left = (area.left + area.right - size) / 2;
        let top = (area.top + area.bottom - size) / 2;
        // 24 视口里的 2px 描边缩到 16px 只有 1.33px，GDI 只能整像素
        let width = ((2.0 * size as f64 / ICON_VIEW * weight).round() as i32).max(1);
        let brush = LOGBRUSH { lbStyle: BS_SOLID, lbColor: tone, lbHatch: 0 };
        let pen = ExtCreatePen(
            (PS_GEOMETRIC | PS_SOLID | PS_ENDCAP_ROUND | PS_JOIN_ROUND) as u32,
            width as u32, &brush, 0, std::ptr::null(),
        );
        /* SelectObject(pen) + SelectObject(NULL_BRUSH) —— 描边不填充 */
    }
    fn x(&self, v: f64) -> i32 { self.left + (v * self.size as f64 / ICON_VIEW).round() as i32 }
    fn line(&self, x1: f64, y1: f64, x2: f64, y2: f64) { /* MoveToEx + LineTo */ }
    fn poly(&self, points: &[(f64, f64)]) { /* Polyline —— 描边，不是 Polygon */ }
    fn circle(&self, cx: f64, cy: f64, r: f64) { /* Ellipse + NULL_BRUSH */ }
    fn round_rect(&self, x: f64, y: f64, w: f64, h: f64, r: f64) { /* RoundRect */ }
}
impl Drop for IconCtx { /* 还原画笔/画刷并 DeleteObject(pen) */ }
```

三个关键点：

1. **`PS_GEOMETRIC` 而不是 `PS_COSMETIC`**。几何钢笔才能有真实宽度和圆头端帽；
   `PS_COSMETIC` 只有 1px，16px 图标上就是用"一个像素"去描 2px 的线，会断、会糊。
2. **`Polyline` 而不是 `Polygon`**。Lucide 图标是**描边**；`Polygon` 会闭合填充，
   方框会变成实心方块、箭头会变成实心三角，整体观感立刻就"不是那个图标"了。
3. **指针单独加粗 1.6 倍**。`MousePointer2` 是个细长轮廓，16px 下 1px 描边认不出是箭头，
   所以 `draw_icon` 里给它单独 `weight = 1.6`，其余图标保持 1.0。

对应关系（全部按 Lucide 原始路径点）：

| 工具 | Lucide 图标 | 画法 |
| --- | --- | --- |
| Select | `MousePointer2` | 四点轮廓 `(4,4)-(20,10.6)-(13.6,12.2)-(12,18.6)`，`weight=1.6` |
| Rect | `Square` | `RoundRect(3,3,18,18,r=2)` |
| Ellipse | `Circle` | `Ellipse(12,12,r=9)` |
| Arrow | `ArrowUpRight` | 折线 `(7,7)-(17,7)-(17,17)` + 对角线 `(7,17)-(17,7)` |
| Pen | `Pencil` | 笔杆六边形 + 笔尖两段线 |
| Text | `Type` | 顶横 + 中竖 + 底横 |
| Mosaic | `ScanLine` | 四角框 + 中线 |
| Undo / Redo | `Undo2` / `Redo2` | 折线箭头 + `arc_points()` 采样的半圆弧 + 尾线 |
| Close | `X` | 两条对角线 |
| Copy | `Copy` | 前层方框 + 后层 L 形折线 |
| Save | `Download` | 下箭头 + 托盘 |
| Insert | `SquarePlus` | 方框 + 加号 |

`arc_points(cx, cy, r, from, to)` 把圆弧采样成 16 段折线再 `Polyline`——GDI 的 `Arc` 方向随
坐标系翻转而变，自己采样最稳，也便于和其它折线拼成一条路径。

#### 做法二：卡片投影用自建 DIB + `AlphaBlend` 还原 `shadow-xl`

GDI 的填充没有半透明，所以投影只能自己合成一张"纯黑 + 逐像素 alpha"的位图：

```rust
fn paint_shadow(hdc: HDC, card: &RECT, radius: i32, scale: f64) {
    let margin   = (20.0 * scale).round().max(6.0) as i32;
    let offset_y = ( 6.0 * scale).round().max(2.0) as i32;
    let blur     = (11.0 * scale).round().max(4.0) as i32;
    // 1) 以圆角矩形为形状算 SDF 距离
    // 2) 距离 >0 用高斯衰减 -(d/blur)^2
    // 3) 峰值 13%（对应两层 10% 叠加）
    data[(y * width + x) as usize] = (falloff * 0.13 * 255.0).round() as u8;
    // 4) 32bpp DIBSection（预乘 alpha：RGB 全 0，只写 alpha）→ AlphaBlend
}
```

距离场用标准圆角矩形 SDF：

```rust
fn round_rect_distance(x: i32, y: i32, rect: (i32, i32, i32, i32), radius: i32) -> f64 {
    let (qx, qy) = /* 相对中心、再减掉 (半宽-半径) */;
    let outside = (qx.max(0.0).powi(2) + qy.max(0.0).powi(2)).sqrt();
    outside + qx.max(qy).min(0.0) - radius
}
```

alpha 图只跟卡片尺寸有关，拖拽时每帧重算 660×96 的 26 万次 `exp()` 太浪费，
按 `(width, height, radius)` 缓存在 `thread_local!` 里：

```rust
thread_local! {
    static SHADOW_ALPHA: RefCell<Option<((i32, i32, i32), Vec<u8>)>> = const { RefCell::new(None) };
}
```

`paint_bar` 第一件事就是 `paint_shadow(hdc, &card, s(CARD_R), ink.scale)`，
之后所有卡片内容都画在投影之上——顺序错了投影会盖住内容。

#### 做法三：主按钮与配色落到 Tailwind 类值

参考项目主按钮是 `<Button>` 默认档：`h-9 px-4 text-sm gap-2 [&_svg]:size-4`，

`WM_SETCURSOR` 不带坐标，坐标得自己问系统：

注意 `ScreenToClient` 在 `windows_sys::Win32::Graphics::Gdi` 里，

#### 做法五：绘制路径改硬拷贝 + 后缓冲降级

两处改动，都指向同一件事：**保证每一帧整块被覆盖**。

```rust
// 1) 源和目标一样大时，SetDIBitsToDevice 逐扫描线硬拷贝，不过缩放器
SetDIBitsToDevice(back, x0, y0, width as u32, height as u32, x0, y0, 0, state.height as u32,
                  state.dim.as_ptr() as *const c_void, &info, DIB_RGB_COLORS);

// 2) 离屏位图建不出来（显存紧张）时退回直接画到窗口 DC，不能整帧 return
let back = back_buffer(hdc, state.width, state.height).unwrap_or(hdc);
let offscreen = back != hdc;
...
if offscreen { BitBlt(hdc, x0, y0, width, height, back, x0, y0, SRCCOPY); }
```

第 2 条是"选区里出现别的内容"最可能的来源：原来 `back_buffer` 失败就 `return`，
这一帧什么都没画，屏幕上留的是上一次的内容——拖拽时正好表现为"框住的地方显示的图没跟上"。

#### 做法六：抓屏重试 + 全黑检测

```rust
for attempt in 0..3 {
    match grab_rect_once(x, y, width, height) {
        Ok(pixels) => {
            if is_blank(&pixels) {
                last = "屏幕内容全黑".into();
                if attempt < 2 { sleep(120ms); continue; }
                return Err("屏幕内容不可抓取（可能正在锁屏或处于安全桌面），已取消本次截图".into());
            }
            if attempt > 0 { logln!("截屏第 {} 次尝试成功（前 {attempt} 次失败：{last}）", attempt + 1); }
            return Ok(pixels);
        }
        Err(message) => { last = message; if attempt < 2 { sleep(90ms); } }
    }
}
```

`is_blank()` 按"每 4096 个像素抽 1 个、RGB 全 ≤2"判定：
锁屏 / 安全桌面 / 独占全屏的典型表现就是"抓取成功但一整屏黑"。
两种情况分开处理——**位图失败重试 90ms，全黑重试 120ms**，
三次都不行才报错，且错误文案直接告诉用户"可能正在锁屏"，而不是一句"截屏失败"。

#### 做法七：像素级自检探针（本轮最有价值的产出）

用户反馈的"选区里出现了没有的内容"在本机**复现不出来**（见下方验证结果）。
与其反复猜，不如把"能不能用机器证明"这件事本身补上：窗口线程每帧把期望值写进全局，
RPC 侧逐个比对实际屏幕像素。

所以标注阶段**第一帧**（此帧刚画出选区、上面还没有任何形状，是最干净的证据）在

`window_probe()` 的取数顺序变成"窗口还在就现场比对，已经关了就用存下的那一帧结论"。

### 8.37 图床破图 / 拖拽内容漂移 / 默认工具 / 钉在顶层 / 文字输入卡死（五项回归）

8.36 把工具栏的视觉规格对齐了，但用户在实际使用中又踩出五个问题，其中两个是**功能性缺陷**
（图床模式下粘贴的图看不到、文字工具一用就把截图窗口弄没），三个是**规格没对上**
（默认工具、缺钉图、输入框不用选中色）。本节逐条定位到根因并修掉，另外在自检过程中
还挖出三个"藏得比较深"的次生 bug（见本节末尾）。

#### 现象（用户反馈）

| 编号 | 现象 | 本轮处理 |
| --- | --- | --- |
| ① | 开启上传图床后，粘贴进笔记的图片显示为**破图**（`screenshot-20261104-195133.png`） | 预览缓存合并为唯一一份 |
| ② | 全局截图拖拽改变选区大小时，选区**下边线**的内容会从**上边线**"滚动退出" | 后缓冲改 DIB 段 + 逐行 `memcpy` |
| ③ | 工具栏默认没有选中「选择」图标，与复刻项目不一致 | 默认工具改 `Select` |
| ④ | 工具栏缺少「钉在顶层」按钮 | 新增原生钉图窗口 + 浮层按钮 |
| ⑤ | 文字输入不用选中的颜色；输完卡死、随后截图窗口消失 | 窗口操作移出 `STATE` 借用 + 上色 + 消息号避让 |

#### 根因

**① 是"两份缓存各记一半"。** `imageStore` 里有一份 `remoteCache`，`previewCache` 里还有一份
`cache`；上传图床成功后 `rememberPreview()` 把 data URL 写进的是**后者**，而编辑器渲染远端地址时
查的是**前者**——查不到就退回"去网上抓一次"，抓不到（或跨域/需要鉴权）就只剩破图。
图片内容明明就在手里（就是刚上传的那份 base64），却因为查错了 Map 而显示不出来。

**② 是 `SetDIBitsToDevice` 的参数语义用错。** 这个 API 的 `ySrc` 是**源矩形左下角**（配合
`biHeight > 0` 的自底向上 DIB），`StartScan` 是**起始扫描线**；旧代码把两者当成同一个"y 起点"传，
选区一变高，源起点就跟着漂，画出来的就是"下边线把内容往上顶出去"。

**③ 是默认值抄错了。** 参考项目是 `const [tool, setTool] = useState<Tool>('select')`，
本插件初始值是绘图工具，所以一进场就高亮了一个"画笔/矩形"。

**④ 是功能没做。** 参考项目 `pin_screenshot` 是 Tauri 多 webview 方案，本插件没有对应实现。

**⑤ 是 `RefCell already mutably borrowed` panic。** `STATE` 是
`thread_local! { static STATE: RefCell<Option<State>> }`；旧代码在 `borrow_mut()` **还没释放**的时候
调 `CreateWindowExW` / `DestroyWindow` / `SetFocus`——这些调用会**同步回灌窗口消息**
（`WM_PARENTNOTIFY`、首次重绘、`WM_CTLCOLOREDIT`），窗口过程再去借 `STATE`，直接
`already mutably borrowed` → 线程 panic → 后端挂死 → 截图窗口跟着消失。用户看到的"输入后卡死、
然后截图退出"就是这个 panic。

#### 做法一：预览缓存合并为唯一一份（对应 ①）

`previewCache` 成为**唯一**的远端图缓存，`imageStore` 不再自己存一份：

```ts
// src/lib/previewCache.ts
const remoteCache = new Map<string, string>()

export async function resolveRemoteImage(url: string): Promise<string | null> {
  const cached = remoteCache.get(url)
  if (cached) return cached
  // 上传图床时 rememberPreview 已经把内容记下来了 —— 直接用，别再走网络
  const remembered = cache.get(url)
  if (remembered) {
    remoteCache.set(url, remembered)
    return remembered
  }
  const result = await rpc.netRequest({ url, timeoutMs: 20_000 })
  /* …解码成 data URL 后同时写两份… */
}
```

`imageStore.persistImage()` 在上传成功的那一刻就把内容塞进预览缓存：

```ts
const uploaded = await rpc.imageUpload({ name, dataBase64, mime, config: hosting })
// 图床回来的地址在宿主里是"外链"，但图片内容就在手里 → 先塞进预览缓存
rememberPreview(uploaded.url, `data:${mime};base64,${dataBase64}`)
return { src: uploaded.url, remote: true, provider: uploaded.provider }
```

`MarkdownEditor` 渲染远端图时统一走 `loadPreview()`（先查缓存，再决定要不要联网）：

```ts

#### 做法二：后缓冲改 DIB 段 + 逐行拷贝（对应 ②）

不再依赖 GDI 的源坐标语义，改成"自己算行偏移，逐行 `memcpy`"——源和目标 1:1，坐标不可能漂：

```rust
struct BackSurface { dc: HDC, bitmap: HBITMAP, old: HGDIOBJ, bits: *mut u8, width: i32, height: i32 }
#[derive(Clone, Copy)]
struct BackView { dc: HDC, bits: *mut u8, width: i32, height: i32 }

fn back_buffer(hdc: HDC, width: i32, height: i32) -> Option<BackView> {
    // CreateDIBSection：biHeight 取负 = 自顶向下，行序和屏幕一致
}

/// 把源图 (x,y,w,h) 逐行拷到后缓冲的**同一坐标**（源目标 1:1）
fn blit_rect(back: &BackView, src: &[u8], src_w: i32, src_h: i32, rect: (i32, i32, i32, i32)) {
    for row in top..bottom {
        let source = ((row as usize * src_w as usize) + left as usize) * 4;
        let target = ((row as usize * back.width as usize) + left as usize) * 4;
        std::ptr::copy_nonoverlapping(src.as_ptr().add(source), back.bits.add(target), bytes);
    }
}
```

没有 DIB 段时的降级路径 `gdi_blit()` 仍用 `SetDIBitsToDevice`，但**参数语义写对**
（`xSrc` 只做横向，纵向交给 `StartScan`），并在注释里写明为什么不能把 `ySrc` 当起点。

#### 做法五：文字输入移出借用 + 上色 + 消息号避让（对应 ⑤）

**(1) 窗口操作全部挪到 `borrow_mut()` 之外。** `begin()` 只改形状，输入框由窗口模块在释放借用后建：

```rust

    if matches!(self.tool, Tool::Text | Tool::Select) { return; }

}

// 三个自由函数，**不在借用内调用**
pub fn create_text_editor(parent: HWND, point: (i32, i32), origin: (i32, i32), size: i32, scale: f64) -> isize

```

**(2) EDIT 子类过程改 `PostMessage`。** `SendMessage` 会把"提交 → `DestroyWindow(自己)`"
同步跑在编辑框自己的键盘处理里，属未定义行为；`PostMessage` 让它回到消息循环里执行。

**(3) 父窗口加 `WS_CLIPCHILDREN`。** 整窗 `BitBlt` 会把正在编辑的 EDIT 子窗口盖掉，
加了这个样式，那块区域不参与父窗口绘制。

**(4) 输入框用选中色。** `WM_CTLCOLOREDIT` 里按 `ink.color` 上色，浅色（亮度 > 170）自动换深底：

```rust
pub fn edit_colors(hdc: HDC, color: [u8; 3]) -> isize {
    let text = cref(((color[0] as u32) << 16) | ((color[1] as u32) << 8) | color[2] as u32);
    let luma = color[0] as f32 * 0.299 + color[1] as f32 * 0.587 + color[2] as f32 * 0.114;
    let background = if luma > 170 { cref(0x18_181b) } else { cref(0xff_ffff) };
    SetTextColor(hdc, text); SetBkColor(hdc, background); SetBkMode(hdc, OPAQUE as i32);
    /* 刷子按 background 缓存，WM_DESTROY 时 DeleteObject */
}
```

**(5) 开输入框时 `ReleaseCapture()`。** 父窗口抓着鼠标的话，点输入框会被父窗口当成"再开一个输入框"。

### 8.38 钉图不置顶 / 拖动后消失 / 标注卡顿 / 文字不能换行

8.37 把钉图"做出来了"，但一上手就露出三个问题：钉出来的窗口压在 DBX 上面而不是屏幕最顶层、
拖一下就没了、标注马赛克和文字时明显发涩。本节把三件事一起收掉，并让文字支持换行。

#### 现象（用户反馈）

| 编号 | 现象 | 本轮处理 |
| --- | --- | --- |
| ① | 钉图钉在了 DBX 窗口上，不是屏幕最顶层 | 落地后显式 `SetWindowPos(HWND_TOPMOST)` + 定时重申 |
| ② | 钉图拖动位置后自己消失，而不是正常 Esc 退出 | 拖动改屏幕坐标 + 补齐关闭按钮 / Esc 焦点 |
| ③ | 截图马赛克、文字调整大小时卡顿 | 已提交标注烘焙到合成层，每帧只 `drawImage` |
| ④ | 文字只能单行 | EDIT 改多行 + Shift+Enter 换行、Enter 提交 |

#### 根因

**① `WS_EX_TOPMOST` 只是"创建时属于置顶层"。** 宿主自己是置顶窗口、或别的程序中途抢了置顶，
新窗口就不在最上面。样式位不等于"永远在最前"，必须落地后再调一次 `SetWindowPos` 把它顶到
`HWND_TOPMOST`，并且**周期重申**（别的程序会抢）。

**② 拖动用的是客户区坐标。** `WM_MOUSEMOVE` 的 `lparam` 是相对窗口客户区的坐标，窗口一移动，
坐标反着变，两相抵消；鼠标移出窗口后坐标变负，`lparam` 取 `u16` 再 `as i32` 会被**零扩展**成
`65531`，窗口被瞬间挪到屏幕外——用户看到的就是"拖一下图就没了"。同时 Esc 只发给**焦点窗口**，
`SetForegroundWindow` 并不授焦点，所以钉图窗口收不到 Esc。

**③ 每帧重跑整条绘制流水线。** 马赛克的 `pixelate()` 是"画布自读回"，拖动时每帧都把所有已提交
标注重画一遍（含读回、模糊），单帧耗时轻松超过 16 ms，肉眼就是卡。后端还在每帧 `CreateFontW`。

**④ EDIT 控件是单行的。** `WS_CHILD | WS_VISIBLE` 默认单行，回车被当成"提交"，输入框里根本
放不下第二行。

#### 改法

- `backend/src/pin.rs` 重写：落地后 `SetWindowPos(hwnd, HWND_TOPMOST, …)` + `SetTimer`（1.5 s）
  周期重申；拖动改成按下时记 `GetCursorPos()` 与 `GetWindowRect()`，移动时用屏幕坐标求差
  `SetWindowPos(SWP_NOSIZE)`；`low()/high()` 走 `as i16` 再 `as i32`，负数不再被零扩展；
  创建与每次 `WM_LBUTTONDOWN` 都补 `SetFocus(hwnd)`，Esc 才收得到；新增右上角悬停关闭按钮
  （`TrackMouseEvent` + 自定义 `WM_MOUSELEAVE = 0x02A3`，`windows-sys 0.59` 没导出这个常量）。
- `backend/src/screenshot_ink.rs`：EDIT 改 `ES_MULTILINE | ES_WANTRETURN | ES_AUTOVSCROLL`，
  `read_edit_text` 过滤 `\r`（`\r\n` → `\n`），`text_lines()` / `line_height()` 逐行绘制，
  Shift+Enter 换行（`GetKeyState(VK_SHIFT) < 0`）、Enter 提交；字体按字号缓存到 `thread_local`，
  `WM_DESTROY` 时释放；新增 `WM_INK_TYPE` 用 `WM_APP + 0x53`（原来是 `0x52`，与
  `WM_INK_SAVE` 撞号，回车被"另存为"分支吞掉）。
- `src/lib/screenshotEditor.ts` 新增 `composeStage()`：把"原图 + 已提交标注"烘焙到离屏 canvas，
  `paintScene({ stage })` 有 stage 就只 `drawImage(stage)`；`canvas.width` 只在尺寸真变时赋值
  （赋同值也会重建后备存储、整块清零）。
- `src/components/dialogs/ScreenshotOverlay.tsx`：`stageRef` / `stageKeyRef` 缓存合成层，
  文字输入换成 `textarea` 面板（对齐参考项目的「取消文字 / 添加文字」）。
- `backend/src/screenshot.rs`：新增探针字段 `pinRects` / `pinTopmost` / `paint{frames,avgMs,maxMs}`。

### 8.39 图片设置面板 / 图像识别双通道 / 记录整理成笔记

这一节的三个问题都指向同一件事：**功能只做了"半条腿"**。图片点不开设置面板、识别只有视觉模型
一条通道、整理成笔记既不看图也把输出当纯文本塞进编辑器。逐条补齐后与参考项目对齐。

#### 现象（用户反馈）

| 编号 | 现象 | 本轮处理 |
| --- | --- | --- |
| ① | 点击图片看不到"图片设置"（地址 / 替代文本 / 宽高） | 新增 `ImageSettingPanel`，点击图片即弹出 |
| ② | 记录里的图片一直显示"图片识别失败"（模型用的是 qwen3-8B） | VLM 失败自动回退系统 OCR |
| ③ | 记录整理成笔记后整篇变成代码块，图床图片也没了 | 剥围栏 + 图片占位回填/补「附图」 |

#### 根因

**② 是"只用了一条腿"。** 参考项目的识别是 `recognizeImageWithFallback`：**先 VLM，返回空或抛错
就回退系统 OCR**。插件只有 `ai/vision` 一条路，而 `qwen3-8B` 是**纯文本模型**，服务端直接
400——于是记录上永远只剩一句"图片识别失败"。系统 OCR（`Windows.Media.Ocr`）根本没用起来，
而这个能力在 Windows 上是现成的。

**③ 有两个原因叠在一起。** 一是提示词里图片只给了路径（`- （时间）assets/x.png`），模型不知道那是
图，自然不会写成 `![](…)`；二是模型常把整篇输出包进 ```` ```markdown ```` 围栏，参考项目
**原样落盘**，于是整篇笔记成了一个巨大的代码块。

#### 改法

- **图片设置面板**（`src/components/editor/ImageSettingPanel.tsx`）：给 `editor.view.dom` 挂原生
  `click`，用 `view.posAtDOM` 换算节点位置（比参考项目逐个 `doc.descendants` 比 `src` 稳，
  本地图会被代理成 data URL，`src` 对不上）；字段「地址 / 替代文本 / 宽 / 高」，按钮
  「重置尺寸 / 删除 / 取消 / 确认」；确认走 `updateAttributes`，重置把 `width/height` 置 `null`，
  删除走 `deleteRange`。
- **Markdown 序列化**（`src/lib/imageAttrs.ts` + `Image.extend({ renderMarkdown })`）：
  无尺寸 → `![alt](src)`；有尺寸 → `<img src alt width height>`（与参考项目一致）。
  解析侧不用额外代码：`@tiptap/markdown` 的 HTML token 会走 `parseHTML`，`width/height`
  属性原样回到节点上。选中图片时隐藏文本气泡工具栏，避免两块浮层叠在图上。
- **系统 OCR**（`backend/src/ocr.rs`）：新增 `ocr/status` 与 `ocr/run` 两个 RPC，走
  `Windows.Media.Ocr`；语言按「简体 → 繁体 → 英文 → 日文 → 韩文」挑一个系统已装的。
  **OCR 跑在独立子进程**（`backend.exe --ocr-once`）里——实测把 1×1 的畸形 PNG 喂给 WinRT，
  进程会以 `0xC0000005` 直接崩掉；放在子进程里崩，主进程只收到"子进程异常退出"，转成一条普通
  错误返回（`sidecar-check` 里专门有一条"OCR 后 Sidecar 仍可响应"）。
- **双通道识别**（`src/lib/imageRecognition.ts`）：VLM 优先（`max_tokens = 120`），返回空或抛错
  回退 OCR；两条都空才写失败文案，并把两边的原因一起写进 `meta.error`。记录上新增
  `meta.method`（`vlm` / `ocr` / `none` / `running`），失败记录直接给一个「重试」。
- **设置 → 图像识别**：拆成「系统 OCR（可用 / 不可用 + 识别语言）」与「视觉模型（VLM，可选）」两段，
  并提示"纯文本模型不支持图片输入，会自动回退 OCR"。
- **整理成笔记**（`src/lib/organizeRecords.ts`）：提示词按类型分组（截图识别 / 文本与待办 /
  链接 / 文件 / 图片），图片记录给 `Image URL` 并要求原样写进正文；落盘前
  `stripCodeFence()` 剥掉整篇围栏、删掉模型照抄的 `Image N:` 行、对没被放进正文的图片补一节
  「附图」——图床图片不会再"消失"。

### 8.40 表格工具栏提示黑块 + 编辑器功能二次对表（搜索替换 / 提示块 / 快捷键）

用户反馈两条：① 表格操作工具栏的提示是**一块纯黑**（截图里「居中对齐」压住了表头）；
② 把编辑器功能再与 `note-gen v0.39.2` 逐项对一遍，把还不一致的地方补齐。

#### ① 提示黑块：真正的原因是"字也是黑的"

| 层 | 现象 | 根因 |
| --- | --- | --- |
| 视觉 | 深色矩形，看不到文字 | `TooltipContent` 用 `bg-foreground text-background`；本项目的主题里 **`background` 没有生成 `text-*` 工具类**，`text-background` 被丢弃 → 文字色退回继承的近黑，和近黑底糊成一块 |
| 形状 | 没有小箭头，像一张贴纸 | `TooltipContent` 少了参考项目的 `TooltipPrimitive.Arrow` |
| 位置 | 压在表头 / 单元格上 | 表格浮动栏的提示走 `Hint` 默认 `side="bottom"`，而工具栏本身就浮在表格上方，提示自然落到表头上 |

改法（`src/components/ui/tooltip.tsx`）：

- 背景 / 文字色改成**内联 CSS 变量**（`backgroundColor: hsl(var(--foreground))`、
  `color: hsl(var(--background))`），不再依赖可能不生成的工具类；深色模式下自动反转成"浅色胶囊 + 深色字"；
- 补 `TooltipPrimitive.Arrow`（`size-2.5` + `rotate-45` + 内联 `fill`），与参考项目的胶囊箭头一致；
- 形状对齐参考项目：`inline-flex w-fit max-w-xs` + `px-3 py-1.5` + `sideOffset = 0` +
  `origin-(--radix-tooltip-content-transform-origin)` + 四向 `slide-in-*`；

#### 一处接口冲突的处理

参考项目 `Mod+F` 是**编辑器内搜索**，而本插件 `Mod+F` 原本是**全局搜索**（文件名 + 正文）。
两者不能同时弹，处理办法是给 `App.tsx` 的全局快捷键处理器加一道 `if (event.defaultPrevented) return`
——编辑器（ProseMirror 的 `handleKeyDown`）先接到按键并 `preventDefault()` 时，全局处理器让位：

- 焦点在编辑器里按 `Ctrl/⌘ + F` → 笔记内搜索替换；
- 焦点在侧栏 / 记录 / 对话里按 `Ctrl/⌘ + F` → 全局搜索（行为不变）。

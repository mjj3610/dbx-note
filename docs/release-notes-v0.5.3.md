# v0.5.3 — 编辑器底栏：复制 / 导出 / 历史版本

## 新增

- **编辑器底栏**：编辑区最下方新增独立一栏，与参考项目 `footer-bar` 的功能和顺序对齐。
  - **复制**：Markdown / HTML / JSON / 纯文本 4 种格式，写入系统剪贴板（宿主能力优先，浏览器 API 兜底）。
  - **导出**：Markdown / HTML / JSON 直接下载；PDF 打开系统打印窗口，选择「另存为 PDF」即可；环境不允许 iframe 打印时自动降级为导出 HTML 并给出提示，不会静默失败。
  - **大纲**：一键切到左侧栏大纲页签，左栏被收起时自动展开。
  - **字符数**：不含空白的实时字数。
  - **历史版本**：右侧入口，见下。
- **本地历史版本**：不配置云同步也能用。每次保存笔记自动留档，可手动「保存当前版本」；
  面板列时间 / 字符数 / 摘要，支持预览全文与恢复，恢复前二次确认。
- **中英文文案**：底栏、导出格式、历史版本全套 zh-CN / en 词条。

## 实现要点

- 复制 / 导出的内容源统一取 `useNotesStore.content`：Tiptap 可视化编辑器 `onUpdate` 会回写
  `getMarkdown()`，CodeMirror 源码模式也用同一份，所以两种模式拿到的都是最新正文。
- HTML 用 `marked` 渲染后经 `DOMPurify` 净化，导出文档不带可执行脚本；JSON 导出的是
  `marked.lexer()` 的结构化 token 树；纯文本按块级标签补换行。
- 历史版本存在本地 SQLite `file_history` 表：空内容不记、与上一条相同不记、自动快照最快
  每分钟一条、单篇最多保留 50 条；手动建版本跳过时间节流但仍去重。
  `history/list` **只返回元信息不返回正文**，点预览才走 `history/get` 按 id 取全文。
- 恢复是高危操作，流程为：当前内容强制留档 → 先 `save({ force: true })` 落盘未保存改动 →
  写回历史正文 → `reloadActive({ force: true })` 强制重载编辑器 → 恢复动作本身再记一条版本。
  因此恢复前的草稿仍能找回，也不会被 800ms 防抖保存覆盖回去。
- 与参考项目的差别：参考项目的历史版本读 GitHub / Gitee / GitLab 的远端 commit 列表，
  本项目读本地快照，**离线可用、恢复不需联网**；顶部标签栏已有可视化 / 源码模式切换，
  底栏不重复放模式按钮。

## 修复

- Windows 剪贴板被剪贴板历史 / 输入法 / 其它进程独占时，`clipboard/write` 的打开重试窗口
  从约 1 秒延长到约 3 秒，明显减少「复制失败：剪贴板被其他程序占用」。
- 底栏「大纲」与左侧栏页签同名，回归脚本里的按名称定位改为显式限定 `.sidebar-tabs`。

## 说明

- 无新增权限（仍是 `permissions: []`）、无新增监听端口，`file_history` 表结构未变
  （0.1.0 已建表，本版只是开始写入），覆盖安装即可。
- 首次升级时历史列表是空的：从升级后第一次保存开始留档，也可以点「保存当前版本」立刻建一条。
- PDF 走浏览器 / 宿主的系统打印窗口，插件本身不生成 PDF 文件；非 Windows 平台的
  复制 / 导出 / 历史版本能力不受桩实现影响，全部可用。

## 1. 变更背景

0.5.1 修好了「打开一篇本地已有笔记时比对并拉取远端内容」，但用户实测反馈：

> 远程仓库的笔记有更新，本地进入时还是没有拉取。

对照参考项目 NoteGen `v0.39.2` 的 `src/stores/article.ts` 后发现，缺的是**更早一步**：

| 环节 | 参考项目 | 0.5.1 本项目 | 0.5.2 |
| --- | --- | --- | --- |
| 进入文件页 | `loadFileTree()` 末尾无条件异步 `loadRemoteSyncFiles()`，拉**远端目录清单** | 无此步骤，`fs/tree` 只读本地磁盘 | 新增 `sync/remoteTree`，`loadTree()` 末尾异步合并 |
| 远端新增笔记 | 合并成 `isLocale: false` 节点，文件树立刻可见 | 完全看不到 | 合并成 `remoteOnly: true` 节点，显示云下载图标 |
| 下载正文 | 点开节点时 `pullMissingRemoteArticle()` 只下这一个文件 | 无入口 | `open()` 判断 `remoteOnly` → 按需下载 → 再读盘 |
| 打开已有笔记 | `syncOnOpen()` 逐文件比对拉取 | 已实现 | 保持，且与自动同步间隔解耦 |
| 自动开关 | `sync_config.autoSync`（总开关）与设置页的「自动同步间隔」是两套；间隔设为「关闭」不影响 `autoPullOnOpen` | `mode` 同时承担「通道」与「是否启用」，间隔关闭时 `mode='off'` 连拉取一起关掉 | 拆成 `channel` 与 `mode`，`pullOnOpen` 只看 `channel` + `autoPullOnOpen` |

另一条反馈是截图：

> 全局截图在没有保存或复制前可以在选取框定位点鼠标标出双箭头模式进行选取区域大小调整。

本项目 8 个定位点本来已经画出来了（`paint_selection(..., handles=true)`），但 `WM_SETCURSOR`
只会在 `IDC_ARROW` / `IDC_CROSS` 之间切换，消息循环也没有 handle 命中与 resize 状态，
所以「看得见、拖不动」。参考项目是 webview 里的 React overlay，本项目是 Win32 原生 GDI
窗口，需要把同一套语义映射到原生消息循环。

## 2. 变更概览

### 2.1 新增

- **Sidecar `sync/remoteTree`**：按当前同步平台分派，返回远端目录清单（元信息，不含正文）。
  - Git：`git fetch` → `git ls-tree -r -l FETCH_HEAD` → 三路比对打状态；
  - 对象存储 / WebDAV / 自托管：读 `manifest.json` → 用 `size:SHA-1` 打状态；
  - 只列笔记与图片（与本地 `fs/tree` 同一套扩展名白名单），过滤隐藏目录；
  - 未配置 / 离线时返回 `configured:false` 或 `offline:true`，不抛错。
- **前端 `lib/tree.ts` 的 `mergeRemoteTree()` / `findTreeNode()`**：清理上一轮云端节点、
  建目录链、插入 `remoteOnly` 节点、给本地节点打 `remoteSha` / `remoteUpdated`。
- **`stores/notes.refreshRemoteTree()`**：只拉清单不读磁盘，带请求代号防慢请求覆盖新结果。
- **窗口回到前台时重拉清单**（`App.tsx` 的 `focus` / `visibilitychange`），并对当前笔记
  再做一次单文件比对；5 秒内不重复触发。
- **文件树云端交互**：云下载图标、「云端有更新」标记、右键「下载到本地 / 下载目录内全部云端文件」；
  云端节点不提供重命名与删除。
- **截图选区 8 向缩放**：`ResizeHandle`、`ResizeState`、`hit_handle()`、`apply_resize()`。
- **`Ink::resize()`**：选区缩放后重裁底片、平移已有标注形状、重排工具栏。
- **Rust 单元测试** 3 项 + **Sidecar 自检** 4 项（远端清单语义）。

### 2.2 修复

- 进入应用 / 回到前台时，远端新增笔记现在能在文件树里看到，点开才下正文（与参考项目一致）。
- 自动同步间隔设为「关闭」不再连带关闭「打开时自动拉取」。
- 全局截图选区在保存 / 复制前可用 8 个定位点拖拽调整大小，鼠标悬停显示系统双箭头。

### 2.3 未变

- 冷启动**不会**自动下载全部远端笔记正文，只拉清单（参考项目语义）。
- 同步基线位置 `.git/dbx-note-sync-state.json`、三路比对算法、冲突弹窗、推送重试均不变。
- 对象存储通道的上传 / 下载逻辑不变，只是新增了「列清单」接口。
- 协议版本、权限（`permissions: []`）、无监听端口等安全属性不变。

## 3. 关键实现

### 3.1 远端清单协议

`sync/remoteTree` 返回结构（两个通道同构）：

| 字段 | 说明 |
| --- | --- |
| `configured` | 是否配置了可用同步平台；`false` 时前端直接跳过合并 |
| `offline` | 远端不可达；前端静默保留本地树，不打扰用户 |
| `channel` | `git` / `store`，供界面区分按需下载方式 |
| `head` / `branch` | Git 通道的远端提交与分支 |
| `files[]` | `{ path, sha, size, mtime, status, localExists }` |
| `localOnly[]` | 本地有、远端没有的文件路径 |

`status` 取值：

| 值 | 含义 | 文件树表现 |
| --- | --- | --- |
| `remoteOnly` | 本地磁盘没有这个文件 | 插入云端节点，云下载图标，点开才下载 |
| `updated` | 本地未改、远端有新版本 | 显示「云端有更新」标记，打开时自动拉取 |
| `conflict` | 两边都改过 | 同样标记，打开时弹冲突窗 |
| `localNewer` | 本地改了、远端没变 | 正常节点 |
| `synced` | 已同步 | 正常节点 |

> 性能：有基线时用一次 blob / 哈希比较，不逐文件跑 `git log`；清单上限 5000 条。

### 3.2 进入时的调用顺序

```
App.boot()
  └─ useNotesStore.loadTree()
       ├─ rpc.readTree()                 // 本地磁盘，阻塞式，决定首屏
       └─ void refreshRemoteTree()      // 不阻塞界面（参考项目 loadFileTree 末尾同款）
            ├─ rpc.syncRemoteTree()     // fetch + 列清单，失败静默
            └─ mergeRemoteTree(tree, files)

App focus / visibilitychange（status === 'ready' 时）
  ├─ refreshRemoteTree()
  └─ pullOnOpen(activePath) → 若 updated 则 reloadActive()

用户点开 remoteOnly 节点
  └─ open(path)
       ├─ pullRemoteFileOnDemand(path)  // 不看 autoPullOnOpen 开关
       ├─ loadTree()                    // 节点转为普通节点
       └─ rpc.readFile(path)
```

`mergeRemoteTree()` 先 `stripRemote()` 清掉上一轮的云端节点与状态标记，再按本次快照重建，
对应参考项目 `mergeRemoteDirectoryEntries()` 里「远端快照里没有的 `isLocale:false` 条目要删掉」。

### 3.3 自动同步开关解耦

| 字段 | 由什么决定 | 用在哪 |
| --- | --- | --- |
| `channel` | `provider`（git / store / off） | 按需下载、打开时比对 |
| `mode` | `channel` + 自动同步间隔是否 > 0 | 仅用于 `scheduleAutoSync()` 的自动推送 |
| `delayMs` | `prefs.autoSync` | 推送延迟 |
| `pullOnOpen` | `channel !== 'off' && prefs.autoPullOnOpen` | 打开 / 回到前台时比对 |

`prefs.autoPullOnOpen` 后端缺省为 `true`，与参考项目 `defaultSyncConfig` 一致。

### 3.4 截图选区缩放（Win32 映射）

参考项目 → 本项目的对应关系：

| 参考项目（React overlay） | 本项目（Win32 GDI） |
| --- | --- |
| 8 个真实 DOM handle | `ResizeHandle::points()`，与 `paint_selection()` 绘制顺序一致 |
| CSS `nwse/nesw/ew/ns-resize` | `IDC_SIZENWSE / IDC_SIZENESW / IDC_SIZEWE / IDC_SIZENS` |
| `setPointerCapture` | `SetCapture(hwnd)` |
| `resizeSelection(rect, handle, delta, viewport)` | `ResizeHandle::apply(start, from, to, screen)` |
| 最小 2px、禁止翻转、限制视口 | 最小 16px（要留得下工具栏与手柄）、`max/min` 夹取、限制虚拟桌面 |
| 拖拽时隐藏 handle 与工具栏 | `state.resizing.is_some()` 时 `handles=false` 且跳过 `ink_paint_bar` |
| 松手后重新渲染 | `WM_LBUTTONUP` 清 `resizing`，整窗重画 + `refresh_probe_annotate()` |

消息循环改动点：

| 消息 | 行为 |
| --- | --- |
| `WM_SETCURSOR` | 先查 `hit_handle()`；命中或正在拖拽时设置对应双箭头，否则沿用原来的箭头 / 十字规则 |
| `WM_LBUTTONDOWN` | 工具栏命中之后、标注工具之前，命中定位点就记下 `start_rect` + `anchor` 并 `SetCapture` |
| `WM_MOUSEMOVE` | `apply_resize()` 按累计 delta 改 `rect`，同步 `Ink::resize()` 与 `ink_layout()`，局部失效重绘 |
| `WM_LBUTTONUP` | 补最后一帧、清拖拽态、整窗重画恢复手柄与工具栏 |

`Ink::resize()` 是必要的：本项目标注画布是**预裁剪的像素缓冲**，不像参考项目能用 CSS 裁剪
DOM 层。缩放后必须按新矩形重裁底片、把 shapes / draft / redo 里的坐标按新旧原点之差平移，
再 `redraw()` 重放，否则标注会留在屏幕原处、新露出的区域发黑。

仅云端节点与 resize 都加了中英文文案（`files.remoteOnly` / `files.remoteUpdated` /
`files.downloadRemote` / `files.downloadRemoteFolder` / `files.pullFailed`），其他语言回退英文。

## 4. 部署与验证

### 4.1 部署

覆盖安装即可，无数据迁移、无 SQL 脚本、无配置格式变更：

```bash
npm install
npm run typecheck
npm run build
npm run backend          # 生成 backend/target/release/backend.exe
```

### 4.2 验证清单

| 场景 | 预期 |
| --- | --- |
| 另一台设备新增笔记并推送，本地重开应用 | 文件树出现云端节点（云下载图标），本地磁盘尚无该文件 |
| 点开云端节点 | 只下载这一个文件并打开，节点转为普通节点 |
| 另一台设备修改本地已有笔记，本地重开应用 | 文件树显示「云端有更新」，当前打开的笔记内容自动更新 |
| 自动同步间隔设为「关闭」 | 打开笔记 / 回到前台仍然会拉取远端更新 |
| 断网启动 | 不报错，本地树正常显示 |
| 全局截图框选完、还没复制 / 保存 | 8 个定位点悬停显示双箭头，可 8 向拖拽改变选区 |
| 缩放后复制 / 插入 | 输出图尺寸等于新选区，已有标注位置正确 |

### 4.3 自动化结果

- `cargo test resize_tests`：3 / 3 通过（8 方向、最小尺寸 / 不翻转 / 不越屏、手柄点位）。
- `scripts/sidecar-check.mjs` 新增 4 项：清单可拉、远端新增标 `remoteOnly`、清单不预下正文、
  清单过滤非笔记文件；另加「下载后条目转为本地已存在」。
- `tsc --noEmit`、`vite build` 通过。
- 前端合并逻辑现场验证（`node --experimental-strip-types` 直接加载 `src/lib/tree.ts`）：
  本地已有节点正确标记 `remoteUpdated`，远端新增的 `云端/b.md` 自动建出目录链并标 `remoteOnly`。

## 5. 已知限制

- 冷启动只拉清单，不自动下载全部正文（与参考项目一致）；需要全量下载请用设置 →
  云同步 →「拉取全部远程文件」，或在云端目录右键「下载目录内全部云端文件」。
- 云端目录的批量下载在 Git 通道会逐文件 `fetch + show`，大目录较慢；对象存储通道是整批下载。
- 截图选区缩放只在「框已拉好、工具栏已出现、还没保存 / 复制」的全局热键路径可用；
  编辑器内点相机按钮的路径松手即把图交回插件浮层，不在原生窗口里停留。
- 非 Windows 平台仍是截图桩实现，本次改动不影响该结论。

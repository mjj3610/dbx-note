### 表结构

```sql
CREATE TABLE IF NOT EXISTS knowledge_sources (
  source_key TEXT PRIMARY KEY, source_type TEXT, source_id TEXT, title TEXT,
  content_hash TEXT, indexed_hash TEXT, status TEXT, error TEXT,
  auto_calc INTEGER DEFAULT 1, included INTEGER DEFAULT 1, updated_at INTEGER
);
CREATE TABLE IF NOT EXISTS vector_documents (
  id INTEGER PRIMARY KEY AUTOINCREMENT, filename TEXT, chunk_id INTEGER,
  content TEXT, embedding TEXT, updated_at INTEGER, UNIQUE (filename, chunk_id)
);
CREATE TABLE IF NOT EXISTS kb_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

`status = 'ready'` 表示已生成向量，`'lexical'` 表示未配置 embedding 时的纯词法降级索引；
`stats()` 两者都计入 `sources`。

## 5. 部署步骤

1. `npm run typecheck` → `npm run build`
2. `npm run backend`（Windows release Sidecar）
3. `npm run sidecar-check` / `npm run smoke` / `npm run e2e`
4. `git tag -a v0.5.6` + 推 Release，等 5 平台 CI 产出 `release-candidates.json`
5. 用 CI 产物生成 `candidates/com.mjj3610.note.json`，提交 `t8y2/dbx-store` 版本更新 PR
6. 维护者 `/sign` 后上架

> 候选 JSON 的 `sha256` / `size` **必须**来自 CI 的 `release-candidates.json`，
> 不能用本机 mingw 产物重新计算；`Validate catalog` 在签名前报
> `open candidate(s) awaiting DBX Store signing` 是预期失败。

## 7. 升级注意

- 旧版 `.dbx-note/kb-index.json` 不再被读写；旧的 `kb/*` RPC 仍可用但底层已换成向量库，
  升级后建议点一次「全部重新计算」。
- 第一次使用需要到「设置 → AI 模型」把某个模型的用途设为「嵌入」并指定为默认嵌入模型；
  未配置时知识库自动走纯词法（BM25）模式。
- `app.settings` 新增 `rag` 字段，`load()` 会与默认值浅合并，老配置不会丢。
- 「在新窗口打开」依赖系统默认程序关联 `.md`；若系统没有关联，会用记事本之类打开。

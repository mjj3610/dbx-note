# 版本部署变更说明 v0.5.9（知识图谱）

> `dev` 已合并 `main`，本版已打 tag / 发 Release / 提商店候选 PR；下文第 6 节记录实际执行结果。
> 商店侧真正上架仍以维护者 `/sign` 为准，见 `store-submission/PUBLISH.md`。

## 1. 版本一致性

发版前必须确认以下 7 处完全一致，否则宿主会报 `Sidecar identity or protocol does not match manifest`：

| 文件 | 字段 | 当前值 |
| --- | --- | --- |
| `manifest.json` | `version` | `0.5.9` |
| `package.json` | `version` | `0.5.9` |
| `package-lock.json` | `version`、`packages[""].version` | `0.5.9` |
| `backend/Cargo.toml` | `version` | `0.5.9` |
| `backend/Cargo.lock` | `dbx-note-backend` 的 `version` | `0.5.9` |
| `backend/src/main.rs` | `PLUGIN_VERSION` | `0.5.9` |
| `.dbx-store.json` | `source` / `releaseNotes` | 已更新为 `v0.5.9` 并追加本版说明 |

第 7 项随本次发布一并更新：候选 JSON 由 `.dbx-store.json` 加上 CI 生成的 5 平台指纹合成。

## 2. 安装与升级影响

- **无新增表、无表结构变更、无 SQL / 迁移脚本**。图谱只读 `vector_documents` / `knowledge_sources` / `kb_meta`，缓存放进程内存。
- **无新增权限**：`manifest.permissions` 仍为 `[]`。`kb/graph` / `kb/graph/neighbors` 是插件自身 Sidecar 的内部 JSON-RPC。
- **无新增 npm 依赖**：`package.json` 与 `package-lock.json` 只改版本号。图谱画布是自写 SVG，不引 d3 / cytoscape / Worker / CDN。
- **无新增配置项**：阈值、粒度、邻居数都是运行时 UI 状态（默认 0.35 / source / 4），不写设置表，不需迁移。
- 老数据直接可用：知识库已有向量 → 向量语义图；只有词法占位 `[0.0]` → 自动降级 BM25 词法图；知识库为空 → 空态引导去设置页计算向量。
- 换 embedding 模型后 `embeddingDimension` 变化会进入水印，旧快照自动失效；与既有 `kb/reindexAll` 的维度 guard 语义一致。

## 3. 新增后端 RPC 契约

```
kb/graph           { granularity?: 'source'|'chunk', threshold?: number,
                     topK?: number, maxNodes?: number, maxEdges?: number,
                     focus?: string }
  → { nodes: GraphNode[], edges: GraphEdge[], meta: GraphMeta }

kb/graph/neighbors { nodeId: string, ...同上 }
  → { nodes, edges, meta }   // 局部 ego 子图，前端按 id 合并
```

- `nodeId` 为空时返回 `invalid` 错误；
- `threshold` 夹到 0~1，`topK` 1~12，`maxNodes` 20~300，`maxEdges` 20~600；
- `meta.watermark` 与 `meta.computedAt` 用于缓存与 stale 判断；
- 超时建议 60s；默认参数下为毫秒级。

## 5. 回滚

纯前端 + 后端增量，回滚只需切换回 v0.5.8 制品：

1. 无需回滚数据库（无 schema 变更，写操作为零）；
2. 无需清理缓存（在进程内存里，重启即消失）；
3. 无需清理设置（图谱参数不持久化）；
4. 回滚代码后 `manifest.json` 与 `PLUGIN_VERSION` 一并回到 `0.5.8`，避免宿主握手版本不一致。

## 6. 正式发版流程（本次已执行，结果见 PUBLISH.md）

1. 合并 `dev` → `main`；
2. 打 `v0.5.9` tag 并创建 Release，等 5 平台 CI 全绿；
3. 更新 `.dbx-store.json` 的 `source` 与 `releaseNotes`；
4. 从 Release 取 `release-candidates.json` 生成 5 平台候选；
5. **先查 `t8y2/dbx-store` 的 #501 状态**：若仍 open 且未 `/sign`，按商店规则先关闭 / 取代，保证同一插件只有一个 open candidate；若已 `/sign` 并合并，则不要动它，直接提新候选；
6. 提交商店候选 PR，等待维护者 `/sign`；
7. 更新 `store-submission/PUBLISH.md` 与 `README.md` 产物行。

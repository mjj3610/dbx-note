## 1. 变更概览

### 1.1 新增

**多标签编辑器（对齐 NoteGen 的 tab-bar）**

- 编辑区顶部新增 48px 标签栏，替换 v0.1.0 的单文件标题栏；打开多个文件会在标签栏追加，不再互相顶替。
- 标签交互：
  - 激活标签：`bg-muted/40` + 加粗 + 底部 2px 主色横条，图标同步变色；
  - 未保存改动显示主色小圆点，悬停时让位给关闭按钮（`×`）；
  - 单击切换、中键关闭、`×` 关闭；标签过多时横向滚动，激活项自动滚入可视区。
- 标签右键菜单：关闭 / 关闭其他 / 关闭左侧 / 关闭右侧 / 关闭全部（不可用项自动置灰）。
- 标签栏 `+` 下拉：新建笔记（落在当前同目录）、切换到记录面板、打开文件夹（目录选择器）。
- 栏右侧沿用原编辑区操作：保存状态（已保存 / 保存中 / 未保存）、可视化 ↔ 源码切换、保存按钮、更多菜单（重命名 / 工作区 / 删除）。

**标签记忆**

- 退出后恢复上次打开的标签与激活项；宿主沙箱没有 `localStorage`，改为存 Sidecar SQLite
  （`settings` 表 key `app.tabs`，值 `{ tabs: string[], activePath: string }`）。
- 启动时若某文件已被外部删除，只丢该标签，不影响其余标签与当前内容。

**快捷键**

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl/⌘ + W` | 关闭当前标签 |
| `Ctrl/⌘ + Shift + W` | 关闭全部标签 |
| `Ctrl/⌘ + Alt + ← / →` | 上一个 / 下一个标签 |

### 1.2 优化

- 编辑器顶部由「标题 + 操作」两行结构合并为一条 48px 标签栏，正文可视高度增加一行。
- Toast 由 `top: 46` 下移到 `top: 92`，不再压住标签栏；深色主题判定改为按实际生效外观（`theme=system` 时也正确）。
- `npm run backend` / `backend:dev` 脚本显式使用 `+stable-x86_64-pc-windows-gnu`：
  Rust 工具链按「当前目录」解析，在仓库根目录执行 `cargo build --manifest-path backend/Cargo.toml`
  时 `backend/rust-toolchain.toml` 不生效，会误选 msvc 并因 Git 自带 `link.exe` 链接失败。
- 清理 `backend/src/main.rs` 的 `unused_mut` 警告（`write_message` 里 `stdout` 无需可变）。

### 1.3 修复

- **标签恢复会带回已删除文件**：`app.tabs` 里残留的路径若已在磁盘上被删除 / 重命名，
  恢复后会出现点不开的空标签；改为启动时对每个路径 `fs/stat` 校验，只恢复真实存在的文件。
- **测试隔离**：`scripts/smoke.mjs` 的深色主题断言会受上一次运行持久化的主题影响；
  改为先归一到浅色再切换，并断言 `html.dark` 与 `body` 背景色同时生效。
- **测试脆弱点**：`scripts/sidecar-check.mjs` 硬编码 `0.1.0`，升版本必挂；
  改为读取 `manifest.json` 的 `id/version` 做比对。
- **测试流程**：`scripts/e2e.mjs` 中「工作区设置」步骤依赖上一个弹窗是否被 Escape 关闭，
  改为显式「设置 → 工作区 → 更换目录」，并在目录选择器结束后连按两次 Escape 关闭两层遮罩。

## 2. 接口变更

**Sidecar 方法：无新增、无删除、无签名变更。**

标签记忆复用既有方法：

| 方法 | 用法 |
| --- | --- |
| `settings/get` | 启动时读 `app.tabs`；不存在时返回 `null`，前端按「无标签」处理 |
| `settings/set` | 标签增删、切换、重命名、删除文件后写回；失败仅打日志，不影响编辑 |

约定补充：

- 标签存储只保存**工作区相对路径**，不保存正文（正文始终以磁盘为准，避免多副本冲突）。
- 切换标签前一定先 `flushPendingSave()`（强制落盘），因此 `fs/write` 调用次数与 v0.1.0 持平。

## 3. 配置与依赖变更

- 运行时配置：`settings` 表新增 key `app.tabs`，示例：

```json
{ "tabs": ["周会纪要.md", "项目/规划.md"], "activePath": "项目/规划.md" }
```

- 前端依赖：无新增（标签栏复用 `@radix-ui/react-context-menu`、`react-resizable-panels` 之外无新包）。
- 后端依赖：无变更。
- 插件清单：`manifest.json` 与 `backend/src/main.rs` 的版本号同步为 `0.2.0`（两者必须一致，否则宿主报
  `Sidecar identity or protocol does not match manifest`）。

## 4. 数据库变更

无 DDL 变更，v0.1.0 的建表脚本可继续使用。仅新增一条运行时数据：

```sql
-- 标签记忆（由 Sidecar 通过 settings/set 写入，无需手工执行）
INSERT INTO settings (key, value, updated_at)
VALUES ('app.tabs', '{"tabs":[],"activePath":""}', 1793606324284)
ON CONFLICT(key) DO UPDATE SET value = excluded.value, updated_at = excluded.updated_at;
```

回滚到 0.1.0 时该 key 会被忽略，无需清理。

## 5. 部署流程

构建顺序与 v0.1.0 相同，注意后端与清单版本必须一起更新：

```bash
npm ci
npm run typecheck
npm run backend        # 固定 GNU 工具链，产出 backend/target/release/backend.exe（约 55s）
npm run build          # 产出 ui/（单文件 bundle）
npm run pack:local     # 产出 release/com.mjj3610.note-0.2.0-windows-x64.dbxp
```

安装 / 升级：

1. DBX 中关闭「笔记」工作台（旧版本先在插件管理里禁用）。
2. 备份 `DBX_PLUGIN_DATA_DIR`（生产：`D:\Program Files\DBX\data\plugin-data\com.mjj3610.note`）。
3. 插件管理 → 从本地安装 → 选择 `com.mjj3610.note-0.2.0-windows-x64.dbxp`。
4. 打开工作台，确认顶部出现标签栏；打开两篇笔记，标签数为 2，切换后正文正确。

回滚：禁用并卸载 0.2.0 → 安装 0.1.0 `.dbxp` → 恢复数据目录备份。
0.2.0 写入的 `app.tabs` 对 0.1.0 无副作用；`workspace/` 下的 Markdown 文件不受影响。

## 7. 已知问题与规避

1. **图片不渲染**：宿主 CSP `default-src 'none'` 覆盖 `img-src`，图片与预览仍不可用（同 0.1.0）。
2. **无拆分视图**：标签页已支持，但 NoteGen 的左右 / 上下分屏未实现；大文件建议用「源码」模式对照。
3. **官方 CLI 打包需 MSVC**：`dbx-plugin dev/package` 固定 msvc target；无 MSVC 时用 `npm run devhost` + `npm run pack:local`。
4. **标签记忆不跨工作区**：`app.tabs` 是全局一份，切换工作区后旧标签会被判为不存在而自动丢弃，符合预期但不做清理提示。
5. **画布 / 知识库 / 同步 / MCP** 未实现，见 README 路线。

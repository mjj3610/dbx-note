## 1. 变更背景

用户给出参考项目编辑器底部状态栏截图，红框标出 **复制 / 导出 / 历史版本**，要求复刻。

只读对照 NoteGen `v0.39.2` 后确认：

| 能力 | 参考项目实现 | 0.5.2 本项目 |
| --- | --- | --- |
| 复制 | `footer-bar/copy-button.tsx`，Markdown / HTML / JSON / Text 4 格式 | 无，只有块手柄的「复制 Markdown」与代码块工具条复制 |
| 导出 | `footer-bar/export-button.tsx`，Markdown / HTML / JSON / PDF 4 格式，`markdown-export.ts` 负责 HTML 内联图片与打印框架 | 无 |
| 历史版本 | `markdown/sync/history-sheet.tsx`，列远端 GitHub / Gitee / GitLab / Gitea commit，可恢复 | 后端 `file_history` 表已建但**从未写入**；`history/list` RPC 存在但前端没有入口 |
| 底栏 | `footer-bar/index.tsx`：左侧模式 / 复制 / 导出 / 大纲，右侧字数 + 同步工具 / 历史版本 | 只有应用级 `StatusBar`；编辑器顶部 `EditorTabBar` 有模式切换、保存状态、字数与更多菜单 |

因此本版做两件事：**新增编辑器内部 bottom footer**，以及**把本地历史版本能力真正跑通**。

## 2. 变更概览

### 2.1 新增

- **`src/lib/markdownExport.ts`**（纯工具层，239 行）
  - `CopyFormat = markdown | html | json | text`；`ExportFormat = markdown | html | json | pdf`。
  - `renderMarkdownHtml()`：`marked.parse()` → `DOMPurify.sanitize()`，导出文件不带脚本 / 事件属性。
  - `toPlainText()`：渲染后按块级闭合标签补 `\n`，再取 `template.content.textContent`。
  - `toJson()`：`JSON.stringify(marked.lexer(md), null, 2)`，导出结构化 token 树。
  - `buildHtmlDocument()`：完整 HTML 文档，带 A4 `@page`、分页避让（`break-inside: avoid-page`）、
    表格 / 代码块 / 引用基础样式，导出的 HTML 与打印 PDF 共用。
  - `downloadText()`：`Blob` + 临时 `<a download>`，与截图浮层同一条已验证可用的下载路径。
  - `printPdf()`：隐藏 iframe 写文档 → 等图片（单张最多 3s）与 `doc.fonts.ready` →
    `win.print()`；沙箱禁 iframe 打印时返回 `false`，由调用方降级导出 HTML。
  - `sanitizeFileName()` / `exportBaseName()`：过滤 Windows / macOS / Linux 交集的非法字符。
- **`src/components/EditorFooterBar.tsx`**：底栏容器 + `CopyMenu` / `ExportMenu` + 大纲按钮 + 字符数 + 右侧 `HistoryMenu`。
- **`src/components/editor/HistoryMenu.tsx`**：历史版本 Popover、预览 Dialog、恢复 ConfirmDialog。
- **`src/components/EditorPane.tsx`**：在编辑区最底部挂 `<EditorFooterBar />`，`activePath` 为空时组件自身返回 `null`。
- **`src/lib/rpc.ts`**：`HistoryItem` / `HistoryVersion` 类型与 `historyList()` / `historyGet()` / `historyCreate()` 绑定。
- **Sidecar `db.rs`**：`history_push()` / `history_get()` / `history_create()`，重写 `history_list()`。
- **Sidecar `files.rs`**：`fs/write` 原子写盘成功后对笔记文件自动留档。
- **Sidecar `main.rs`**：新增 `history/get`、`history/create` 分发；`PLUGIN_VERSION` → `0.5.3`。
- **i18n**：zh-CN / en 各 34 条底栏与历史版本文案。
- **回归**：Sidecar 自检 +9 项历史版本断言、smoke +1 项底栏断言、e2e +12 项底栏与历史版本交互断言。

### 2.2 修复

- **Windows 剪贴板争用**：`native.rs::open_clipboard()` 的 `OpenClipboard` 重试由
  `25 × 40ms ≈ 1s` 提升到 `75 × 40ms ≈ 3s`。Windows 剪贴板是全局独占资源，剪贴板历史、
  输入法、截图工具或其它版本插件的 Sidecar 都可能持续持有；重试太短会把环境占用误判成功能缺陷。
  `sidecar-check.mjs` 对该错误改为明确「环境跳过」，不再污染回归结论。
- **测试定位歧义**：底栏「大纲」与左侧栏页签同名，`smoke.mjs` 的
  `getByRole('button', { name: '大纲' })` 在 strict mode 下同时命中两个按钮；
  改为 `page.locator('.sidebar-tabs').getByRole(...)` 精确限定作用域。

### 2.3 未变

- 顶部 `EditorTabBar` 的可视化 / 源码模式切换保留，底栏**不重复放模式按钮**
  （参考项目把模式放在底栏，本项目放在顶部，同一屏出现两个入口反而混乱）。
- 云同步、远端清单、冲突处理、截图 8 向缩放、图床、AI 多模型配置全部不变。
- 协议版本、`permissions: []`、无监听端口、宿主页面不持有文件 / 网络权限等安全属性不变。

## 3. 关键实现

### 3.1 内容源：始终取最新 Markdown

参考项目的 footer 拿到的是 `editor` 实例与 `sourceMarkdown`，需要 `getMarkdown()` 兜底。
本项目统一取 `useNotesStore.content`：

```
Tiptap onUpdate ── getMarkdown() ──┐
                                    ├─→ useNotesStore.content ─→ 复制 / 导出 / 历史版本
CodeMirror onChange ───────────────┘
```

因此可视化与源码模式共用一份源文本，不需要把 Tiptap Editor 传进工具层。

### 3.2 复制 / 导出格式映射

| 格式 | 复制 | 导出 | 生成方式 |
| --- | --- | --- | --- |
| Markdown | ✓ | `.md` | 原文 `content` |
| HTML | ✓ | `.html` | `marked` + `DOMPurify` 片段；导出时包成完整文档 |
| JSON | ✓ | `.json` | `marked.lexer()` token 树 |
| 纯文本 | ✓ | — | 渲染 HTML → 块级补换行 → `textContent` |
| PDF | — | 系统打印 | 完整 HTML → 隐藏 iframe → `print()`；不可用则降级导出 HTML |

复制走 `copyText()`（宿主剪贴板能力优先，浏览器 `navigator.clipboard` 兜底），
导出走 `downloadText()`；两条链路都给 toast 反馈，失败时显示具体错误。

### 3.3 历史版本快照策略

`file_history(id, path, content, created_at)` 表 0.1.0 就建好了，本版才接入写入。

| 规则 | 值 / 行为 |
| --- | --- |
| 触发点 | `fs/write` 里 `fs::rename(&temp, &path)` **成功之后**，仅 `TEXT_EXTENSIONS`（`md` / `markdown` / `txt` / `mdx`） |
| 失败隔离 | 快照失败只写日志，绝不影响正常保存 |
| 去重 | 与上一条 `content` 相同则不记 |
| 自动节流 | 距上一条不足 `HISTORY_MIN_INTERVAL_MS = 60_000` 不记 |
| 手动建版本 | `history/create` 传 `force = true`，跳过时间节流但仍去重 |
| 条数上限 | 每文件 `HISTORY_MAX_PER_FILE = 50` 条，写入后 `DELETE ... NOT IN (最近 50 条)` |
| 摘要 | `history_preview()` 折叠空白后取 `HISTORY_PREVIEW_CHARS = 80` 字符 |
| 空内容 | 不记 |

RPC 语义：

| RPC | 入参 | 返回 |
| --- | --- | --- |
| `history/list` | `path`、`limit`（默认 20） | `items[]`：`id` / `preview` / `size` / `createdAt`，**不含正文** |
| `history/get` | `id` | `id` / `path` / `content` / `createdAt`；`id <= 0` 明确报 invalid |
| `history/create` | `path`、`content` | `{ created: boolean }`，`false` 表示内容未变 |

### 3.4 恢复流程（可回退、不被防抖保存覆盖）

1. 用户点「恢复此版本」→ `ConfirmDialog` 二次确认（标题 + 时间 + 「会立即写盘」说明）。
2. `historyCreate(path, 当前编辑器内容)` **强制留档**：自动快照有 1 分钟节流，不能靠它兜底。
3. `useNotesStore.save({ force: true })`：先把编辑器里尚未落盘的改动写盘，
   否则 800ms 防抖保存会在恢复之后把旧内容写回去。
4. `historyGet(id)` 取历史正文 → `rpc.writeFile(path, version.content)`。
5. `reloadActive({ force: true })` 强制重载编辑器，避免脏内存内容残留。
6. `historyCreate(path, version.content)` 给恢复动作本身记一条版本，时间线连续。
7. 刷新列表、关弹窗、toast 提示。任一步失败都留在当前状态并报具体错误。

## 5. 已知限制

- **升级后历史为空**：0.5.3 之前 `file_history` 从未写入，无法补回升级前的编辑历史；
  从升级后第一次保存开始留档，或点「保存当前版本」立刻建一条。
- **本地快照不是远端 commit**：与参考项目的 `HistorySheet` 不同，本版不列 Git 提交历史、
  不显示作者 / commit message，也不依赖云同步；好处是离线可用、恢复不联网。
- **PDF 由系统打印窗口生成**：插件不直接产出 `.pdf` 文件，用户需在打印窗口选「另存为 PDF」；
  iframe 打印被禁用时降级为 HTML。
- **历史正文全文存 SQLite**：单篇最多 50 条，长笔记会占用一定数据目录空间；
  清空笔记内容不会产生新快照（空内容不记）。
- **剪贴板仍是全局独占资源**：`clipboard/write` 已把重试窗口提到约 3 秒，
  但被其它进程长期持有时会如实报错，属 Windows 系统限制。

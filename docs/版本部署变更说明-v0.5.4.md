## 1. 变更背景

用户反馈 0.5.3 的「历史版本与原参考项目功能不一样，导出的功能也有差异，导出的文件保存在哪里」。
重新只读对照 NoteGen `v0.39.2` 后确认：

| 能力 | 参考项目 | 0.5.3 本项目 | 0.5.4 处理 |
| --- | --- | --- | --- |
| 导出落盘 | `markdown-export.ts` 桌面端 `save()` 系统另存为 + `writeTextFile()`；浏览器才 Blob 下载 | `Blob` + `<a download>`，DBX iframe 无 `allow-downloads` 时可能不落盘，且没有明确位置 | 改走 `dialog/saveFile`，Sidecar 弹系统对话框并写盘，回显实际路径；非 Windows 降级 Blob 并提示 |
| 导出 JSON | Tiptap JSON 文档 | `marked.lexer()` token 树 | 改 `MarkdownManager.parse()` |
| 导出 HTML | 内联工作区图片、收集页面样式 | 图片保持相对路径，离开工作区即丢图 | 相对图片经 `fs/readImage` 转 data URL |
| 历史版本数据源 | 远端 GitHub / Gitee / GitLab / Gitea 对当前文件的 commit 列表 | 本地 SQLite `file_history` 自动快照 | 改远端 commit 历史，`git fetch` + `git log` + `git show` |
| 历史版本展示 | 短 sha / message / author / date / commit URL / 「在仓库中打开」/ 按 fullSha 恢复 | 时间 / 字符数 / 摘要 / 预览 / 手动建版本 | 按参考项目重做；保留二次确认作为本项目增强 |
| 入口可见性 | 非 Git 托管平台 `return null` | 始终显示 | 由后端 `history/status` 判定，不满足时整个入口不渲染 |

用户选择：**历史版本与参考项目一致**、**导出走系统另存为对话框**。

## 2. 变更概览

### 2.1 新增

- **`backend/src/githistory.rs`**（296 行）：远端提交历史与按 sha 取正文。
  - `history/status` → `{ supported, provider, repoUrl, branch }` 或 `{ supported:false, reason }`。
  - `history/commits` → 最近 10 条 `{ sha, shortSha, message, author, date, url }` + `fileUrl`。
  - `history/content` → 按完整 sha 返回 `{ sha, path, content, size }`。
  - 支持 `github` / `gitee` / `gitlab` / `gitea`；`parse_remote()` 兼容 https、带 userinfo 的 token URL、
    `git@host:owner/repo.git`、GitLab 子组；`commit_url()` / `blob_url()` 按平台拼路径。
  - `git_root()` 用 `sync::same_path()` 校验工作区是**独立** Git 仓库，避免误读外层插件源码仓库。
- **`backend/src/native.rs`**：`dialog/saveFile`。
  - Windows 调 `GetSaveFileNameW`（`OFN_EXPLORER | OFN_OVERWRITEPROMPT | OFN_PATHMUSTEXIST | OFN_NOCHANGEDIR`），
    先 `CoInitializeEx`、结束 `CoUninitialize`，默认目录为用户 Downloads；用户删掉后缀时自动补回。
  - 扩展名白名单 `md / html / json / txt`，正文上限 16 MiB，默认文件名过滤目录分隔符与控制字符。
  - 取消返回 `{ saved:false, cancelled:true }`；`DBX_NOTE_EXPORT_AUTO_DIR` 时写固定目录供自动化。
- **`backend/src/native_stub.rs`**：同名 `save_text_file` 返回 `unsupported:true`，前端降级 Blob 下载。
- **`src/components/editor/HistorySheet.tsx`**（替代 `HistoryMenu.tsx`）：远端 commit 面板，
  宽屏 Popover / 窄屏贴底 Drawer，监听 `focus`、`visibilitychange`、`dbx:sync-options-changed`
  重新判定入口。
- **`src/lib/rpc.ts`**：`historyStatus` / `historyCommits` / `historyContent` / `saveTextFile`；
  `syncSaveOptions()` 成功后派发 `dbx:sync-options-changed`。
- **i18n**：`footer.exportSavedAt`、`exportSuccessFallback`、`exportPdfOpened`、
  `footer.history.openCommit` / `openInRepo` / `noMessage` / `restoring` 等，zh-CN 与 en 各 33 条对齐。

  `contentForCopy()` / `renderMarkdownHtml()` 改为异步；`toJson()` 改 Tiptap JSON；
  `saveTextExport()` 优先 `rpc.saveTextFile()`；`printPdf()` 补 `afterprint` 清理与图片 / 字体等待。

## 3. 关键实现

### 3.1 导出链路

```
EditorFooterBar → exportMarkdown(format, { path, markdown })
  ├─ markdown ─→ saveTextExport → rpc.saveTextFile({ defaultName, extension, filterName, content })
  ├─ html     ─→ buildHtmlDocument(await renderMarkdownHtml(md, path))
  │                └─ inlineWorkspaceImages(): <img src="assets/x.png"> → fs/readImage → data URL
  ├─ json     ─→ toJson(): MarkdownManager.parse(md) → Tiptap JSON
  └─ pdf      ─→ printPdf(html) → 隐藏 iframe + win.print()
                   └─ 打印不可用 → 降级导出 HTML（明确提示）
```

`dialog/saveFile` 在 Windows 由 Sidecar 弹系统模态框并 `std::fs::write()` 写盘，
返回绝对路径；前端把它放进 `footer.exportSavedAt` 的 toast。取消时 `saved:false`，
`EditorFooterBar` 直接 `return`，不写盘也不弹成功提示。
非 Windows 桩返回 `unsupported:true`，`saveTextExport()` 退到 `downloadText()` 并标 `fallback`。

### 3.2 为什么用 git 命令而不是四套 REST 客户端

参考项目读的是四家平台 REST API 的「某文件 commit 列表」。本项目工作区本身就是 Git 仓库，
已有 `origin` 与同步令牌，因此：

```
git fetch --prune <target> <branch>       → FETCH_HEAD（失败则退回 origin/<branch> 或 HEAD）
git log -n10 --format=%H%x1f%an%x1f%aI%x1f%s <remote-ref> -- <path>
git show <sha>:<path>                     → 该次提交的笔记正文
```

拿到的是**同一份远端提交历史**，且自建 Git 服务、已 fetch 的离线历史同样可用。
`DBX_NOTE_HISTORY_OFFLINE=1` 时跳过联网 fetch，直接读本地引用，供自动化使用。
`git log` 字段用 `\x1f` 分隔，控制字符不会出现在提交说明里。

### 3.3 入口判定

`history/status` 依次校验：工作区是独立 Git 仓库 → `provider ∈ {github,gitee,gitlab,gitea}` →
`origin` 存在且 URL 可解析。任一不满足返回 `supported:false`，`HistorySheet` 直接 `return null`。
面板每次打开重新拉列表；切换笔记、同步配置变化、窗口回到前台都会重新判定。

### 3.4 恢复流程

```
historyContent(path, sha) 取远端版本正文
  → save({ force:true }) 先把编辑器未落盘改动写盘
  → writeFile(path, version.content) 落盘历史正文
  → reloadActive({ force:true }) 强制重载编辑器
```

恢复前二次确认，避免误覆盖；恢复**不会**自动创建新的 Git 提交，需要保留当前版本请自行 commit / push。

## 4. 部署与验证

### 4.1 部署

覆盖安装新 `.dbxp` 即可，无需数据迁移、无需改权限。升级后：

- 没配置 Git 远端时，「历史版本」入口不显示（预期行为，不是故障）；
- 在设置页配置 GitHub / Gitee / GitLab / Gitea 同步、让工作区成为独立 Git 仓库并设置 `origin` 后，
  窗口回到前台或重新打开笔记即会出现入口；
- 导出会弹系统「另存为」，保存位置以对话框选择和 toast 回显为准。

### 4.2 验证清单

| 导出 Markdown / HTML / JSON | 弹系统另存为，选定后文件真的落盘，toast 显示绝对路径 |

## 5. 已知限制

- 历史版本依赖远端 Git 仓库：工作区不是独立 Git 仓库、没设 `origin`，或使用对象存储 /
  WebDAV / 自托管通道时入口隐藏（与参考项目一致）。
- 提交历史以「已 fetch 到的远端引用」为准：离线时能看到上次 fetch 的记录，新提交需联网
  `fetch` 后刷新面板。
- macOS / Linux 暂不提供系统另存为对话框，导出降级为浏览器下载；CI 的 5 平台包仍正常产出。
- `dialog/saveFile` 单次正文上限 16 MiB，`history/content` 上限 8 MiB；超限会明确报错。
- 本地 `file_history` 表仍在每次保存时写快照，但前端已无入口消费；后续版本可视情况下线。

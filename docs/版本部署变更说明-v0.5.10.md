# 版本部署变更说明 v0.5.10（打开笔记 / 上传文件性能）

> 本版只有前端行为与版本号变更，**未打 tag、未发 Release、未提商店候选 PR**。
> **本地安装包已构建并落盘到宿主目录供验证**，见第 7 节。
> 详细说明见 `docs/release-notes-v0.5.10.md`。

## 1. 版本一致性

| 文件 | 字段 | 当前值 |
| --- | --- | --- |
| `manifest.json` | `version` | `0.5.10` |
| `package.json` | `version` | `0.5.10` |
| `package-lock.json` | `version`、`packages[""].version` | `0.5.10` |
| `backend/Cargo.toml` | `version` | `0.5.10` |
| `backend/Cargo.lock` | `dbx-note-backend` 的 `version` | `0.5.10` |
| `backend/src/main.rs` | `PLUGIN_VERSION` | `0.5.10` |

`.dbx-store.json` 仍指向已发布的 v0.5.9；本版正式发布时再更新 `source` /
`releaseNotes` 与 5 平台指纹。

## 2. 安装与升级影响

- **无新增表、无表结构变更、无 SQL / 迁移脚本**；Sidecar 协议零变化。
- **无新增权限**：`manifest.permissions` 仍为 `[]`。
- **无新增 npm 依赖**：`package.json` / `package-lock.json` 只改版本号。
- **无新增 RPC、无新增设置项**，老数据 / 老设置直接可用。
- 升级后首次打开笔记会立刻渲染本地正文，远端比对转为后台执行：
  若远端确有更新，编辑器会在比对完成后被替换（等价于旧版行为，只是更晚）；
  若用户已经开始输入，则弹冲突对话框，不再静默覆盖。
- 导入 / 下载完成后文件树按后端返回路径增量更新，不再全量重扫磁盘、
  也不再额外触发远端清单请求；若之后需要刷新远端状态，仍可点文件树顶部的重试入口。

## 5. 回滚

本版尚未发布，也无数据结构变更。若需回到 v0.5.9：

```bash
git checkout v0.5.9
```

或在宿主里删除 `versions/0.5.10/` 与对应 `activations/*.json`（生成安装包并手动安装后），
宿主会回落到上一激活版本。

## 6. 发布前置

第 1~3 步已完成（见第 7 节），后续仅需：

1. 用户确认后打 tag / Release，等 5 平台 CI 全绿；
2. 用 `release-candidates.json` 合成候选 PR，注意发布前核对 #507 是否已被 `/sign` 或合并；
3. `.dbx-store.json` 更新 `source` / `releaseNotes` 到 v0.5.10。

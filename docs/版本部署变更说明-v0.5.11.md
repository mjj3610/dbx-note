# 版本部署变更说明 v0.5.11（原生文件选择 / 刷新可见反馈）

> 本版新增 1 个 Sidecar RPC，**未打 tag、未发 Release、未提商店候选 PR**。
> **本地安装包已构建并落盘到宿主目录供验证**，见第 7 节。
> 详细说明见 `docs/release-notes-v0.5.11.md`。

## 2. 安装与升级影响

- **无新增表、无表结构变更、无 SQL / 迁移脚本**；
- **无新增权限**：`manifest.permissions` 仍为 `[]`；原生文件对话框由 Sidecar 调 Win32 API，
  不经过 DBX 权限声明；
- **无新增 npm 依赖**；
- **新增 1 个 RPC**：`dialog/openFiles`。旧 UI 调不到新 RPC 时会抛错并回退 DOM input，
  因此新旧前后端混搭不会崩；
- 升级后「上传 / 导入」优先弹 Sidecar 原生 Win32 多选对话框，
  非 Windows 与自动化环境回退 DOM input；
- 文件夹选择仍走 DOM `webkitdirectory`，因为 Win32 `GetOpenFileNameW` 不支持选文件夹；
- 刷新按钮有忙碌态和成功 / 失败 toast，内容没变化时也能看到反馈。

## 4. 验证

```bash
npm run typecheck          # 0 错误
npm run build              # 通过
cd backend && cargo +stable-x86_64-pc-windows-gnu test --bin backend   # 28 / 0
DBX_NOTE_BACKEND=backend/target/debug/backend.exe \
DBX_NOTE_CHECK_DATA=.tmp/check-0511b \
DBX_NOTE_PICKER_AUTO=1 npm run sidecar-check                           # 216 / 0
npm run smoke                                                          # 38 / 0
node scripts/e2e.mjs                                                   # 351 / 0
```

跑 e2e 的 devhost 必须带：

```bash
DBX_NOTE_EXPORT_AUTO_DIR="$PWD/.tmp/e2e-exports"
DBX_NOTE_HISTORY_OFFLINE=1
DBX_NOTE_PICKER_AUTO=1
```

否则导出会弹真实系统模态框、上传会弹真实原生对话框，卡住 Sidecar。

## 5. 回滚

本版尚未发布，也无数据结构变更。若需回到 v0.5.10：

```bash
git checkout v0.5.10
```

或在宿主里删除 `versions/0.5.11/` 与 sequence 40 的 `activations/*.json`
（生成安装包并手动安装后），宿主会回落到上一激活版本。

## 6. 发布前置

第 1~3 步已完成（见第 7 节），后续仅需：

1. 用户确认后打 tag / Release，等 5 平台 CI 全绿；
2. 用 `release-candidates.json` 合成候选 PR，注意发布前核对 #507 是否已被 `/sign` 或合并；
3. `.dbx-store.json` 更新 `source` / `releaseNotes` 到 v0.5.11。
